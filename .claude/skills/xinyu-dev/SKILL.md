## 项目一句话

用户打开一个网页，和一个"愿意听"的角色聊天。系统在**倾听（listener）/ 引导（guide）/ 危机（crisis）**三种状态间自动迁移；每条要发出去的回复，先过**规则 + LLM 复核**的双重审查，不合格就重写，危机直接短路并给资源。

- 技术：Python 3.11 + Streamlit + DeepSeek + 本地 JSON，6 个文件
- 特色：否决权唯一的审查层；只升不降的风险地板；8 字段白名单记忆
- 交付：4 周 + 3 天，在线可访问 + 5 分钟录屏 + 8 节报告

## 当前真实状态

**本文件不维护独立状态。** 唯一状态源是 `.claude/CLAUDE.md` 的 2.2 分步骤表与 4 当前进度。本文件只讲"怎么做、做到什么算过、哪里会踩坑"。

## 全局硬规则（每一步都适用）

### 三条铁律

1. **只升不降**：规则异常、LLM 超时、JSON 解析失败——任何一种失败都只能把等级往上推。代码里每次判断等级，旁边要有注释说明"为什么这里不能降"。
2. **否决权唯一**：`guardian` 说不发，就不发。不许"综合评分"、不许"多数通过"、不许上层覆盖。
3. **责任不越界**：`coordinator` 只管角色，`guardian` 只管内容。二者不得互相调用。

### 术语（写代码注释、报告、PPT 都一样）

| 不写 | 写 |
|---|---|
| 多智能体 / Agent 1..5 | 三段职责隔离 / `listener`、`guide`、`crisis` |
| 多模态 | 静态资源路由 |
| 诊断 / 抑郁倾向 / 你有…症 | 本轮出现需要关注的表达 |
| 缓解焦虑 / 疗效 | 完成交互功能验证 |

### 安全

- 任何"对用户下结论"的句子都不许出现，包括人设的 `mes_example` 里。
- 危机回复必须含**至少一个**可用资源；资源电话改动前先核验。
- 规则宁可漏、不许滥杀；但 **L3 宁可误报**。

### 技术

- 不加依赖。要用新库先问，答案基本是"用标准库或现有库凑"。
- 所有外部调用有超时与兜底；所有 JSON 解析有 `try/except`。
- 单文件 ≤350 行、单函数 ≤40 行；超了拆。
- 不打印用户原文；日志只记字段与 `session_hash`。

## 第 1 周：培训 + 空壳

**目标**：一个能聊天、能记住一句话、能在线打开的网页。**不写任何安全逻辑。**

### 1.1 建仓与骨架（第一天上午）

```text
git init → GitHub Desktop 建私有仓 → 六文件空壳 + tests/ + data/
```

六个文件先只放**函数签名 + 最小实现**，让 `contract_check.py` 能 import 成功：

| 文件 | 本周只需要这些 |
|---|---|
| `memory.py` | `read_memory / write_memory / update_memory / clear_memory / match_lore` |
| `agent.py` | `call_llm / build_system_prompt` |
| `coordinator.py` | `coordinator_decide`（永远返回 listener） |
| `guardian.py` | `guardian_pre_check / guardian_post_check`（永远 pass） |
| `resources.py` | `pick_resources`（返回空列表） |
| `roles.py` | `PERSONAS` 五个 key、`RULES = []`、`THEMES` 三套 |

**为什么先搭空壳**：契约是 6 个人并行开发的地基。签名定了，各自写各自的，最后能拼上。

### 1.2 `call_llm` 的三件事

1. 读环境变量（`LLM_API_KEY / LLM_BASE_URL / LLM_MODEL`）；超时用 `roles.TIMEOUT=15`，不读环境变量。缺 key 时给**人话错误**，不是 traceback。
2. `MOCK_LLM=1` 时**完全不发请求**，按角色返回预置短句（每个角色 3 条轮换），延迟 0.3 秒模拟打字。
3. 返回 `{text, ok, error, latency_ms}` 四个键，异常不外抛，`ok=False` + 兜底文案。

### 1.3 `build_system_prompt` 的分区（本周只搭骨架）

顺序固定：**安全区 → 风格区 → 事实区 → 历史 → PHI → 用户**。
本周只需两段：安全区（免责 + 不诊断）+ 风格区（人设）。中间用明确分隔符，便于 W3 打印检查。

### 1.4 `contract_check.py`

- 用 `inspect.signature` 比对 11 个函数的参数名与顺序，不做类型检查。
- 输出必须是 `11/11 signatures OK` 或 `10/11 ... missing: guardian_post_check`。
- 任一模块 import 失败要报"哪个文件、哪一行"，不要只抛 ImportError。

### 1.5 Streamlit 页面

- 顶部 `st.caption` 常驻免责声明（不要折叠、不要滚出视野才看到）。
- `st.chat_message` 渲染历史；`st.chat_input` 收输入。
- 侧栏：当前角色、风险灯、主题选择、"清空记忆"按钮。
- **会话 id 放 `st.session_state`**，首次生成 uuid；刷新不换 id（否则记忆断）。

### 1.6 部署

Streamlit Cloud 连仓库 → Secrets 里填 `LLM_API_KEY` → 拿公网链接。**部署要放在周三**，别留到周五。

## 第 2 周：状态机 + 拦截

**目标**：能演示"危机暗示 → 拦截 → 含热线的回复"。

### 2.1 `RULES` 20 条的写法

每条一个 dict：

```python
{"id": "S01", "level": "L3", "pattern": r"(不想活|活着没意思|想死)", "why": "自杀意念"}
```

- 只写**短语级**正则，不写整句匹配；不写需要语义才成立的模式。
- 分成 L3（明确危险）/ L2（持续低落、自伤暗示）/ L1（普通负面情绪）三档。
- 每条必须有 `why`（日志与报告要用）。
- **一条规则只干一件事**。复合条件拆成两条。

### 2.2 四类豁免（先跑豁免，再跑命中）

1. **否定/假设**：`不想死`、`不会自杀`、`如果…就好了`
2. **第三人称**：`我朋友说他想死`（降一级处理，不直接 L3）
3. **引用/转述**：`电影里那个人说…`、`歌词`
4. **夸张/口语**：`笑死`、`累死了`、`社死`

实现顺序：`豁免正则命中 → 打标 not_crisis → 再跑 RULES`。**豁免不是删除命中，是给命中降权/降级并记录**，日志里要能看出"命中了但被豁免"。

### 2.3 L3 短路

命中 L3 且未被豁免 → **不进 LLM 生成**，直接返回危机模板 + 资源卡。

- 模板三句：承认感受 / 明确建议联系真人 / 给资源。不超过 120 字。
- 资源卡优先级：校心理中心 > 12356 > 120/110。
- 同时把 `role` 置 `crisis`、`level` 置 L3、写日志。

### 2.4 状态机

`coordinator_decide(memory, user_text, level) -> {role, reason}`

| 当前 | 条件 | 去向 |
|---|---|---|
| listener | level L3 | crisis |
| listener | level L2 连续 2 轮 或 用户明确要建议 | guide |
| guide | 用户情绪转负 或 连续 3 轮无进展 | listener |
| crisis | 任何情况 | 保持 crisis（**只能人工/新会话退出**） |
| 任意 | 用户点"换个角色" | 人工指定，reason 记 `manual` |

- 每次切换必须写 `role_switch_reason`（枚举：`crisis_shortcircuit / user_ask_advice / sustained_negative / manual / cooldown`）。
- **禁止**：crisis 直接回 guide；禁止同一轮切两次。

### 2.5 五套人设

- id 固定：`sister_heart / warm_senpai / rational_mentor / energy_buddy / quiet_hollow`
- 每卡字段：`name / tone / address / sentence_len / emoji / boundaries / taboos / mes_example / post_history_instructions`
- `boundaries` 五卡相同（安全层），`taboos` 每卡微调（体验层）。
- `mes_example` 每卡 3 轮，硬规则：不出现建议句、每轮留开口、不出现诊断词。

- [ ] C-09 → 切 crisis（截图）
- [ ] C-01"我不想死" → **不**切 crisis（截图）
- [ ] `guardian_log.jsonl` 有 `rule_ids` 与 `level`，**无中文原文**
- [ ] 侧栏显示角色与切换原因
- [ ] 三个人设各 3 条回复，盲读 ≥2/3 能分对
- [ ] 断网 MOCK 可演示（30 秒录屏）
- [ ] tag `v0.2`

### 本步骤的坑

- **正则写太宽会误杀**：`死` 单独成词会命中"笑死"。要用词组边界：`(想死|不想活|活不下去)`。
- **别把"我朋友想自杀"直接 L3**：会显得系统不懂语境。降到 L2 + 建议陪同求助。
- **crisis 别自动退出**：演示时最容易翻车——用户说句"我饿了"，系统就回去聊天了，评委一眼看出安全是假的。
- **中文标点**：用户会打"，。"也会打",."，正则可以不管，但豁免里的"不想死"要兼容"不想 死"（可选，别过度）。

## 第 3 周：复核 + 记忆 + 主题

**目标**：Guardian 会改自己写的回复；记忆有结构；界面像个人做的。

### 3.1 `guardian_post_check`

输入：`user_text, reply, level, role` → 输出 `{pass, reason, fixed_reply}`

流程：

1. **规则复查**：回复里出现诊断词、药物、绝对化承诺 → 不通过。
2. **LLM 复核**（可选但建议）：让它只回答 JSON `{"pass": bool, "reason": str}`。
3. **不通过 → 重写 1 次**：把拒因塞进 prompt（"上一版因为 X 被拒，改写时避免"）。
4. **复检**：改写后再跑一遍规则；仍不过 → 用模板兜底，**不再调 LLM**。
5. **记账**：日志写 `rewrite=0/1/2`、`reason_codes`、`template_fallback=true/false`。

再加一层"说教词"检查（不进 RULES，不影响 20 条指标的召回/误拦）：
`(你应该|你必须|别想太多|这没什么|我当年|你要坚强|振作起来)` → 触发 rewrite。

### 3.2 会话聚合（防止一句话定生死）

- `N_WINDOW=5`：看最近 5 轮的等级分布，不是单轮。
- 规则：窗口 5 轮内 L2 出现 ≥3 次 → 升 L3；出现 1 次 L3 → 直接 L3。（用 3 不用 2：一天两次"没意思"很正常）
- `COOLDOWN=3`：L3 之后 3 轮内风险地板保持 L2；冷却只按轮数走，不因"我没事了"提前降。
- **只升不降的落点**：`level = max(historical_level, current_level)`，且 `historical_level` 只在会话重置时清空。

### 3.3 记忆（白名单）

- 只有 8 个字段 + `summary_at_turn`；任何"再多存一点"的冲动都要拒绝。
- `update_memory` 里先 `scrub()`：正则去掉手机号、身份证、地名候选、人名候选（"我叫X"、"我室友X"）。
- `rolling_summary` 每 5 轮压一次（`SUMMARY_EVERY=5`），或超 200 字（`SUMMARY_MAX=200`），或**首次进入 crisis 立即压一次**。
- 写文件：先写 `.tmp` 再 `os.replace`；每天首次读时备份到 `memory_backup/`。
- 损坏恢复：JSON 解析失败 → 用备份 → 备份也坏 → 返回 `DEFAULT_MEMORY` 并记日志，**不崩页面**。

### 3.4 迷你 Lorebook

- 8 条种子事实（"考试周在 1 月"、"学校心理中心在 X 楼"这类）。
- 命中规则：子串命中、最多 2 条、注入 ≤100 字、同会话最多 3 次。
- **只由 `update_memory` 写**，不许 LLM 自己往里加。

### 3.5 主题

- 三套 CSS 变量，切换只改 `:root` 变量，不改 DOM 结构。
- 圆角 16–20px、动效 200–400ms；暗色主题下对比度自己先看一眼。

- [ ] 连续 5 轮弱信号，第 3 轮起风险灯变黄
- [ ] L3 之后第 2 轮聊"今天吃什么"，等级仍为 L2 以上

### 本步骤的坑

- **重写循环会烧钱**：最多 1 次重写 + 1 次复检，超了走模板。别写 `while not pass`。
- **LLM 复核返回非 JSON 是常态**：一定要 `try/except`，解析失败按"不通过"处理（只升不降）。
- **摘要会吃掉细节**：200 字压完经常丢"用户在意什么"。压缩 prompt 里明确要求保留"担忧的事 + 想要的语气"。
- **主题切换后 Streamlit 会重跑整个脚本**：切换值要进 `session_state`，否则闪回。

## 安全模块专项（改 `guardian.py` / `RULES` 前必读）

### 三条不可协商

1. **顺序**：豁免 → 规则 → 分级 → 短路 / 生成 → 复核 → 重写 → 复检 → 兜底。顺序错了，误杀率立刻上去。
2. **失败方向**：任何异常（正则编译失败、LLM 超时、JSON 坏）→ 等级 +1，不允许 -1。
3. **日志不含原文**：只写 `session_hash`、`rule_ids`、`level`、`action`、`rewrite`、`latency_ms`。

### 改一条规则的标准动作

1. 先写一条**会失败的测试**（期望命中/不命中）。
2. 改 `RULES`（只允许 P3 改，改一次补一条回归用例）。
3. 跑 28 条，看召回与误拦是否都在阈值内。
4. 在 PR 描述里贴数字：召回 x/20、误拦 y/8。

### 常见设计错误

- 用 LLM 判危当唯一防线 → 断网即失效，评委一问就露。
- 把"绝望"当 L3 → 误杀一片，用户会觉得被冒犯。
- 危机回复里写"我理解你"却不给电话 → 等于没救。
- 重写后不再检查 → 改出新问题。

## 记忆模块专项

- 白名单是硬的：加字段 = 改契约 = 全组返工。想加先问队长。
- 摘要只写"事实 + 用户偏好"，不写情绪形容词。
- 清空要连备份一起删，并在界面二次确认。
- 同一 session 并发写：用文件锁或"后写覆盖 + 版本号"，别让 JSON 半边坏掉。

## 演示与答辩专项

### 三幕（每幕 ≤90 秒）

| 幕 | 内容 | 要看到的证据 |
|---|---|---|
| A 普通陪伴 | 用户说"最近好累"，listener 接住，不问诊 | 语气自然、无建议轰炸 |
| B 角色迁移 | 用户求建议 → guide 给一个可执行的小步骤 | 侧栏 role 变化 + reason |
| C 危机短路 | 输入 C-09 → 直接出资源卡、不进 LLM | 日志 level=L3、latency 很短 |

### 四问（答案要能在 10 秒内翻到）

1. 为什么不是多 Agent？→ 三段职责隔离的判据是"是否改变下游行为"，不是实例数。
2. 安全怎么保证？→ 规则独立可跑 + 只升不降 + 重写复检 + 模板兜底。
3. 记忆会不会泄露？→ 8 字段白名单 + scrub + 不含原文 + 可删可清空。
4. 局限是什么？→ 测试集自建、无真实用户、无临床验证、中文口语覆盖有限。

### 翻车预案

- 网络挂 → `MOCK_LLM=1`（练 3 次，10 秒内切完）。
- 页面卡 → 切到录屏对应片段。
- 评委问"这算医疗吗" → "不是，我们不诊断、不给药、不承诺疗效"。

## 常见故障排查

| 现象 | 先查 |
|---|---|
| 页面空白 / 转圈 | Streamlit 日志；`st.session_state` 里是否有未初始化变量 |
| 回复是兜底文案 | `MOCK_LLM` 是否为 1；API key 与 base_url；超时 15s 是否太短 |
| 危机不触发 | 豁免是否过宽；规则 pattern 是否被中文空格打断；level 是否被聚合逻辑覆盖 |
| 记忆不落盘 | `DATA_DIR` 是否存在；写权限；是否写成 `.tmp` 没 replace |
| 角色乱跳 | `coordinator` 是否每轮都重算；`historical_level` 是否被清 |
| 部署后 500 | Secrets 是否配；依赖是否写进 `requirements.txt`；Python 版本 |

## 不要做的事

- 不引入 LangChain / 向量库 / 前端框架（4 周做不完，且会掩盖真正的设计）。
- 不做"多 Agent 投票"，不假装有自主规划。
- 不追求"更像真人"而牺牲边界；人设只改语气，不改安全。
- 不在最后一周加功能；不在演示前一天改规则。
- 不把真实聊天记录、真实姓名、真实学校贴进仓库或截图。
