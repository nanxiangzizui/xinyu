## 3 发现并当场修的安全类缺口（唯一一处）

**现象**：`app.py` 原来只在 `result.get("short_circuit")`（即 L3）时渲染资源卡。第 4 条（第三人称、L2）按 `step/S10-precheck-shortcircuit.md:147` 的失败表应当"L2/L3 当轮各出一次资源卡"，实际 0 卡。

**改动**（`app.py:304-307`）：

```python
# [SAFE] S10 §8：L2/L3 当轮各出一次资源卡（L2 两张 / L3 三张），L1 为空不打扰。
# 卡只渲染在本轮，不写进 messages，刷新重绘时不会重复弹（S21 #4 补的口径）。
for card in pick_resources(result["level"], []):
    st.info(f"{card['title']}：{card['detail']}")
```

`pick_resources` 对 L1 返回 `[]`，所以去掉 if 不会打扰平稳轮。新增 `tests/test_guardian.py::test_resources_by_level_are_wired`（L3 三张含 12356 / L2 含 0571-87713518 / L1 空）。

修复后复跑：第 4 条 2 卡、第 5/6/7/12 条 3 卡，全绿。

## 5 口径修正（写清楚，避免下次重踩）

1. **步骤 §3 的 `65 passed` 是旧基数**，实际 95（S20 结束 94 + 本步 1）。
2. **L2 资源卡**：S10 的失败表要求"只在 L2/L3 那一轮渲染一次"，但代码只在 L3 短路分支渲染 —— 属安全类缺口，按 S21 §4.2 当场修。
3. **断网普通轮不是 `FALLBACK_LINE`**：LLM 返回空文本 → `guardian_post_check` 命中 `empty_reply` → 模型重写也失败 → 走 `SAFE_FALLBACK["listener"]`（"我在。你愿意说多少都可以，不想说也没关系。"），日志 `action=template_fallback`，`degraded=True` 触发侧栏网络提示。比 `safe_handle` 的兜底句更安全，保留。
4. **E2E 必须等"生成真的结束"**：Streamlit 在调用 LLM 前就把助手气泡连 spinner 一起挂上，只数 `stChatMessage` 会把占位气泡当回复；更严重的是，生成中再发一句会打断上一轮，留下"有问无答"的会话（首跑 #7 即因此超时）。改用 `waitIdle`（`stSpinner` 计数为 0 且消息数连续两次不变）后 12/12 通过。
5. **刷新后轮次是第 0 轮但记忆还在**：`turn` 属 `session_state`，`memory.json` 才是持久层（S05 既定口径）；面板仍读到偏好与摘要，说明验收项"记忆在"成立。
6. **#3 引导者没给建议**：`coordinator` 只负责"现在是谁"，话术由人设决定；知心姐姐的 `post_history_instructions` 要求"先确认情绪，再开口；不要急着给办法"（`roles.py:41`）。按 S21 §4.3 记为**体验类问题**、不修；若 W4 时间够，可给 guide 换一版更"给结构"的默认人设或在 prompt 里加一条"被明确求助时给 1 条可执行建议"。
7. **硬要求 4（验收人不是写代码的人）本次未满足**：脚本由编码会话执行。已在 §6 列为待办，需队内另一人按本文复跑一遍并签字。
