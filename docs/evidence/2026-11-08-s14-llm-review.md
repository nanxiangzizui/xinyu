# S14 · LLM 复核 + LLM 重写（证据）

> 文件名沿用计划日期 2026-11-09 的系列口径；**本文件实际生成于 2026-11-08**。

## 1 这一步做了什么

S13 的 `guardian_post_check` 五步链里只接了规则复查与"注入式 rewriter"，S14 把两处空位补成真调用：

| 产出 | 位置 | 说明 |
|---|---|---|
| `llm_review(user_text, reply, level, *, budget_s)` | `guardian.py` | 模型自查回复；所有失败路径 `pass=False` |
| `llm_rewrite(user_text, reply, reasons, role, *, budget_s)` | `guardian.py` | 带拒因重写一次；失败返回 `None` |
| `_bounded_call(messages, temperature, budget_s)` | `guardian.py` | 用守护线程 `join(budget)` 卡墙钟，**总预算 5 秒**落在调用上 |
| `REVIEW_SYS` / `REWRITE_SYS` / `MOCK_REVIEW_BAD` / `MOCK_REWRITE_LINE` | `agent.py` | prompt 与 MOCK 剧本放同一处，避免两处 prompt 漂移 |

五步链（升级后）：

```text
① 规则复查 _violations     → 有 bad 直接进重写（规则优先于模型）
② 无 bad 且 level != L3    → llm_review；pass 即放行；不过则把模型给的原因塞进 bad
③ 无 bad 且 level == L3    → 直接放行（模板固定，复核只多一次等待）
④ 剩余预算 > 0             → 重写一次（注入的 rewriter 优先，否则 llm_rewrite）
⑤ 复检重写句               → 通过就发重写句，否则发 SAFE_FALLBACK[role]
```

## 2 五条硬要求逐条对账（step/S14 §4）

| # | 要求 | 实现 | 证明 |
|---|---|---|---|
| 1 | 任何异常一律"不通过" | 超时/ok=False→`review_call_failed`；非 JSON/非 bool→`review_parse_failed`；异常→`review_error_{类型}` | `test_review_timeout_falls_back`、`test_review_garbage_json_falls_back` |
| 2 | 复核 prompt 不带记忆与历史 | `_review_messages` 只有 system + "用户说/助手回复/风险等级"三行 | `test_review_rejection_triggers_rewrite` 逐字断言 messages |
| 3 | 规则优先于模型 | 有 bad 时不调复核；模型说 pass 也进重写 | `test_rules_beat_model_review`（只调重写 1 次） |
| 4 | 重写写明"改哪些" | user 消息含 `需要修正：{reasons}` + `角色：{role}` + "保持原意" | 同上，断言 `agent.REWRITE_SYS` 与 messages |
| 5 | 复核+重写总预算 5 秒 | `LLM_BUDGET_S = 5.0`；复核用整预算，重写只用 `5.0 - 已耗时`；`_bounded_call` 线程 join 超时即 None | `test_slow_model_is_cut_by_budget`（预算 0.1s，慢模型 0.5s，实测 <0.4s 返回兜底） |

## 5 真实模型耗时（`docs/evidence/probes/_probe_s14_real.py`，DeepSeek）

```text

```

出口要求"单轮平均耗时 < 6 秒"：真实复核 + 重写合计 **2.36s**；即使重写被切断也由 `_bounded_call` 保证 5 秒内出兜底。

## 6 三处口径修正（写进代码注释）

1. **`bool(data["pass"])` 会把字符串 `"false"` 当成通过**（step §5.1 示例写法）。改成 `isinstance(data.get("pass"), bool)`：模型返回字符串就按解析失败处理，判据必须可执行。
2. **step §5.3 示例没有第 5 条硬要求的预算实现**。补 `_bounded_call`（守护线程 + join），并把重写预算设为"5 秒减已耗时"；否则一次 15 秒超时会让界面白等。
3. **L3 无 bad 时不能掉进重写分支**。第一版把 `review = None if level == "L3"` 之后直接往下走，导致 `CRISIS_REPLY` 被 MOCK 重写句替换后缺 12356 → 模板哨兵变红。改为"复核 None 或 pass → 立即返回 pass"。

## 7 没做的事

- 没有做"多轮重写"（step §8：循环重试会把"模型反复犯规"变成"跑到超时"）。
- 没有把 `llm_review` 接进 `app.py` 的独立分支：它只在 `guardian_post_check` 内跑，`app.py` 只认 `action` / `rewrite`。
- 真实模型的"复核判不通过"未单独采样（MOCK 已覆盖两条拒因路径，真实模型只验证了 pass 与重写）。
