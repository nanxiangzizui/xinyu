## 3. 视频怎么做的（方法要说清楚）

**不是桌面录屏软件录的**，是「真实页面逐帧截图 + 真实命令输出渲染 + TTS 旁白」，按同一份 `demo_timeline.json` 对齐：

1. 起两个真实服务：`8601` 真实 DeepSeek key（`MOCK_LLM=0`）、`8602` 指向不可达端点（模拟断网）。
2. `%TEMP%\s26\capture.js`（playwright-core + 本机 Edge，headless，viewport 1280×720）：一个循环按 timeline 执行动作（逐字输入、回车、展开记忆面板、切服务），另一个循环每 200ms 截一帧并存时间戳 → **1190 帧，覆盖 0–237.809s**。
3. `%TEMP%\s26\render_terminal.py`（PIL）：238–288s 的终端段，内容逐字来自真实输出 —— `132 passed in 5.19s`、`11/11 signatures OK` / `5/5 constants OK` / `20/20 rules OK`、`recall 10/10 = 100.0%` / `false_block 0/20 = 0.0%` / `role 12/12 = 100.0%` / `stable 10/10 = 100.0%`。
4. 旁白：`System.Speech` + `Microsoft Huihui Desktop`（Rate 1），25 句逐句成 wav，再按 timeline 铺到 300 秒轨上（`build_audio.py` 报 `overlaps []`，语音结束 294.89s）。
5. `build_video.py`：按时间戳二分取帧 → 1500 帧序列 → ffmpeg（ffmpeg-static 6.1.1）`libx264 crf 23 + aac`。

**理由**：本机没有录屏软件、也没有带采集的 ffmpeg；逐帧截图可以让「断网切换」只发生在页面内部（不露端口号），也不会把微信通知、任务栏、个人信息录进去。代价是**画面里没有鼠标光标**，输入是逐字出现（每字 70ms），观感像自动演示而不是人手操作 —— 这一点如实写在这里，报告与答辩都不掩饰。
