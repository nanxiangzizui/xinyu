## 6 口径说明

1. **列表上限**：步骤 §4 写“列表 ≤ 8 项”，§5.5 写 `unresolved_issues` 最多 5；执行书 §5.1 的字段表是
   `emotion_tags 5 / unresolved_issues 3 / coping_preferences 5`。按“执行书是数字唯一出处”取 **5 / 3 / 5**，
   均不超过 8。S17 摘要压缩与 S18 面板按这组上限显示。
2. **字段集合**：只保留 8 个白名单字段 + `summary_at_turn`（CLAUDE.md §5.5）。执行书 §5.1 示例里的
   `session_id / persona_id / crisis_flag / turn` 未落盘：会话 id 在文件名里，人设由 `persona_id` 参数传入，
   `crisis_flag` 由 S16 的等级地板承担。**加字段 = 改契约，先问队长。**
3. **写失败方向**：`read_memory` 永不抛异常（四类边界之一）；`write_memory` 的 `OSError` 只记日志、
   不冒到界面，避免磁盘满/被杀毒占用时聊天中断。`ValueError`（非法 id）仍然抛出——这是调用方的编程错误。
4. **时间**：`last_updated` 统一 UTC ISO8601（`+00:00`），界面显示时再转本地。
5. **控制台乱码**：PowerShell 管道按 cp936 解码 UTF-8 输出，属显示问题；加 `PYTHONIOENCODING=utf-8`
   后正常，文件本身始终是 UTF-8（`ensure_ascii=False`）。
6. **顺带修 `.gitignore`**：原规则只忽略 `data/memory/*.json`，S03 新增的 `.bak` / `.tmp` 会漏进仓库。
   已补 `data/memory/*.bak` 与 `data/memory/*.tmp`；`git check-ignore` 验证两份运行时文件均被忽略。
7. **`summary_at_turn` 语义（跨步骤冲突）**：S03 决策表写“每轮 + 1”，但执行书 §5.1.1 与 S17 的
   `turn - summary_at_turn >= SUMMARY_EVERY`、S18 的“概况更新于第几轮”都要求它是**上次压缩所在轮次**。
   若每轮自增，S17 的节流永远不触发。按权威顺序（执行书 > 步骤细节）**不自增**，只在 S17 压缩成功后由
   S17 赋值；S03 的 9 条测试不依赖该计数器。
