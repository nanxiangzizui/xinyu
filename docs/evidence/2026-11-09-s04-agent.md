## 6 实现中的三个判断

1. **`max_retries` 必须放客户端构造**：本机 `openai 1.109.1` 的
   `chat.completions.create()` 签名里**没有** `max_retries`（`inspect` 实测），只有 `timeout`。
   步骤 §5.2 示例把两者都传给 `create()`，会抛 `TypeError` 并被 `except` 吞成
   `ok=False, error="TypeError"`——真实调用看起来像网络故障。因此 `timeout=15` 与
   `max_retries=1` 都放在 `OpenAI(...)` 构造上，`create()` 只传业务参数。
2. **MOCK 用 md5 而不是内置 `hash()`**：内置 `hash(str)` 受 `PYTHONHASHSEED` 影响，
   每次新进程都不一样，违反“同样输入同样输出”的硬要求（步骤 §4.4）。改为
   `md5(last.encode("utf-8"))`，跨进程稳定。
3. **缺 Key 在 `try` 之前抛**：`RuntimeError` 不被兜底吞掉，也不会悄悄转 MOCK；
   只有网络/API 异常才走 `ok=False`。`error` 只放异常类型名，避免把 Key 或原文带进日志。

## 7 口径说明

- **MOCK 延迟**：按步骤 §5.3/§6 返回 `latency_ms=0`，不 `sleep`；SKILL §1.2 的“0.3 秒模拟打字”
  留给 S05 在界面层做，测试与调用层保持零等待。
- **`load_dotenv()` 位置**：放在 `agent.py` import 处且默认 `override=False`。测试先 import、
  再 `monkeypatch` 环境变量，因此第 4 条用例能稳定命中“无 Key”分支；生产环境变量仍优先于 `.env`。
- **`safe_json` 的非 dict 结果**：JSON 合法但根不是对象（如 `[1,2]`、`"ok"`）时返回 `None`，
  调用方（S14）按“解析失败 = 中风险”处理，不许当无事。
- **`build_system_prompt` 未动**：S04 明确不做真实拼接，S07 再实现安全区 / 风格区分区。
