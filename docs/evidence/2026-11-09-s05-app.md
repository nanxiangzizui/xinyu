## 4 三条边界

### 4.1 刷新：同 sid，记忆在，聊天记录本来就不恢复

```text
[refresh] sid_same= True
[refresh] chat_messages_after_refresh= 0
[refresh] panel_emotion_tags= ['人际']
[refresh] panel_has_raw_text= False
```

真实浏览器 `Page.reload` 后 URL 仍为 `?u=demo-s05`，侧栏会话号不变；聊天区为空是**设计行为**
（系统不存原文，`session_state` 刷新即空，见步骤 §8 的口径说明）。记忆面板从磁盘读回同一份标签。
截图：`2026-11-09-s05-refresh.png`。

### 4.2 清空：旧文件真删，换新会话

```text
[clear] old_file_gone= True sid_changed= True messages= 0 exceptions= 0
```

点“清空这次对话”后，`data/memory/<旧 sid>.json` / `.bak` / `.tmp` 全部删除，URL 换成新 sid。
**为什么换 sid**：侧栏每轮都会 `read_memory(sid)`，如果沿用旧 sid，删完文件后同一次 rerun 会立刻
按默认值重建一个同名文件，验收项“文件消失”就永远不成立。换 sid 后旧文件保持删除状态，页面从零开始。

### 4.3 缺 Key 且非 MOCK：启动即报错（2026-11-08 修订）

**修订前**：`call_llm` 抛 `RuntimeError` → `safe_handle` 接住 → 界面一句“卡了一下”，侧栏“网络不稳定”。
问题：把**配置错误伪装成网络故障**，演示前排查会跑错方向，也违反 `.cursor/rules/xinyu.mdc` §8.2
「缺 Key 且非 MOCK 必须启动即报错」。

**修订后**：`app._config_gate()` 在首屏检查，缺 Key 时 `st.error` + `st.stop()`，不渲染输入框。实测：

```text
[no-key] exceptions= 0
[no-key] errors= ['未配置 LLM_API_KEY：请在 .env 填入 Key，或设 MOCK_LLM=1 离线运行。']
[no-key] chat_input= 0
```

`call_llm` 仍保留“缺 Key 直接抛”的行为（单测 `test_missing_key_raises_runtime_error` 覆盖），
启动门只是让这个错误在用户开口之前就暴露。

## 6 实现中的判断

1. **会话 id 放 `st.query_params`，不放 `st.session_state`**：步骤 §5.2 与 W1 的“刷新后记忆还在”
   都要求 URL 持久化；`session_state` 刷新即空。`?u=` 的值先按 `^[a-zA-Z0-9_-]{1,32}$` 校验
   再交给 `memory`，防止 URL 注入 `../`。
2. **清空换新 sid**：见 §4.2。副作用是侧栏会话号会变，这是“新开一次对话”的合理语义；
   `clear_memory` 仍然把旧 sid 的三个文件全部删掉。
3. **异常路径记 L2**：`safe_handle` 捕获后返回 `level="L2"`。判危没跑完时风险未知，
   按“只升不降”不能记 L1；界面仍只给通用兜底句，不冒充危机模板（危机模板是 S10 的职责）。
4. **侧栏角色/等级仍是占位**：按步骤 §5.5，`listener` / `L1` 写死，S12 再接真实值与中文标签。
   管线本身已经返回真实 `level` / `role`，S12 只需在 `main` 里存一轮即可。
5. **聊天记录不落盘**：`st.session_state.messages` 只用于本屏显示；记忆只写标签与摘要。
   刷新丢聊天记录是已知口径，侧栏已明示，报告里按步骤 §8 写清楚，不当 bug。
6. **MOCK 断网**：`agent._is_mock()` 在 `call_llm` 最前面返回，根本不构造 `OpenAI` 客户端，
   因此 MOCK 路径没有任何网络依赖；第 3 节的 10 轮全程未联网。
