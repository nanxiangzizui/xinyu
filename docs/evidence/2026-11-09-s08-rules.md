## 2 规则表口径

- 条数与分组：**X 5 / H 10 / W 5 = 20**，顺序固定 **X → H → W**。
- 字段（11 个，一个不少）：`rule_id / group / pattern / intensity / level / action / exempt / source / version / case_ids / why`。
- `source` 统一 `"执行书附录B"`；`version` 统一 `"v1"`。
- `case_ids` 全部来自附录 B 的“回归用例”列；**H01 额外含 `C-09`**，因为附录 C 明确写“C-09 命中 H01”，不是编造。

- `exempt` 为空字符串是合法值（H/W 组不豁免），因此校验只检查字段存在，不要求非空。

## 6 两处实现口径修正（相对 S08 步骤示例）

1. **顺序检查不能用 `sorted()`**：示例写 `sorted(group)`，但字母序是 `H < W < X`，正确的 X→H→W 表会被误报“顺序错”。改为按 `GROUP_ORDER = {"X": 0, "H": 1, "W": 2}` 的显式序号比较；故障注入 3 验证过。
2. **`COMPILED` 不能让 import 崩溃**：模块级字典推导遇到坏正则会直接抛 `re.error`，`validate_rules()` 根本没机会运行。改为 `_compile_rules()` 容错构建，坏正则跳过、由校验函数报具体 `rule_id`；故障注入 1 验证过。
