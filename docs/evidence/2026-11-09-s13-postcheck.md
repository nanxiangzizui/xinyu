`guardian_post_check` 五步（`pass=False` 的含义是“原回复不可用”，不是“不发消息”）：

```text
_violations(原文)  →  空 → pass=True / rewrite=0
                   →  非空 → rewriter(user_text, reply, bad, role) 只调 1 次
                              → 重写句过复检 → pass=True / rewrite=1 / fixed_reply=重写
                              → 重写句也不过 → pass=False / template_fallback=True / fixed_reply=SAFE_FALLBACK[role]
```

`SAFE_FALLBACK["crisis"]` 直接复用 `CRISIS_REPLY`：兜底与短路必须同一句话，否则同一个危机在两条路径上两种说法。

## 4 口径修正（已记录）

1. **`action` 四值**：`app.py` 原本固定写 `action="generate"`，与执行书 §4.7 / §5.6（`pass / rewrite / template_fallback / short_circuit`）冲突。
   本步改正，优先级：`template_fallback > rewrite > pass`——两者同时为真时，这一轮真正发出去的是模板句。
   `docs/evidence/2026-11-09-s12-logging-sidebar.md` 里的历史输出保留 `generate` 原样，不追改。
2. **`rewrite` 只记“真的重写过”**：本步 `rewriter=None`，所以被拦时是 `rewrite=0` + `template_fallback=True`；
   S14 接上 LLM 重写后才会出现 `rewrite=1`。W3 验收的“重写日志 `rewrite=1`”留给 S14 截图。
3. **`pass=False` 不是“不发”**：三段返回都能发，区别只在 `fixed_reply` 用哪句。`st.markdown` 只拿 `fixed or 原文`，
   原文在没有 `fixed_reply` 时才出现。
