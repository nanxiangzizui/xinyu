### 5.1 第一次 A 抽取 0 条（已修）

第一次探针 A 段 5 轮后 `A_episodes=0`。复放同一段对话，模型原始输出两条都被 8 字原句闸门拒掉：

```text
RAW: {"episodes":[
 {"cue":"搬家","event":"对方下个月要搬家，最近在收拾东西，觉得搬家那几天会很乱",...},
 {"cue":"新住处","event":"新住处离公司更近，通勤能省半小时，希望搬完能睡个好觉",...}]}
cue_in_blob: True quote: True
cue_in_blob: True quote: True
```

原因：模型保留了「下个月要搬家，最近」「希望搬完能睡个好觉」这类 8–9 字连续片段。**闸门没有错，是 prompt 不够硬**。`A_SYS` 改成：
- “不要保留连续 6 个字以上的片段”；
- 给一条原话 → 转述的示例；
- 要求输出前逐条自检，有 8 字连续重合就重写。

复放结果：两条都通过，`quote=False`。

### 5.2 A 写入与召回

第二次探针：

```text
A_episodes=2 cues=['搬家', '通勤']
A_recall='（下面有对方以前提过的事……）
对方以前提过：对方下个月要换住处，近期在整理物品，翻到旧照片时有些感触'
A_last_len=10 last_try=0
```

定向召回探针（重置冷却，输入带 cue）：

```text
QUESTION: 搬家的事我还是有点慌，你还记得吗？
REPLY: 慌是正常的，换地方谁都会。今天先收拾哪一块？
USED=True
```

结论：cue 命中时块确实进了 prompt，回复用了“换地方”这一转述；**不声称语义召回**——用户不提 cue（例如只问“你还记得我下个月要做什么吗”）不会触发。

## 6. 隐私闸门

| 闸门 | 覆盖 | 证据 |
|---|---|---|
| 自报姓名 denylist | “我叫 X / 叫我 X / 我的名字是 X / 我姓 X” | `test_user_real_name_not_stored`、`test_parse_a_rejects_self_name`、探针 `张三=False` |
| 8 字原句 | 情景/摘要/线索与用户原句连续 8 字重合 | `test_parse_a_rejects_quote`、`test_episode_store` 清洗用例、5.1 的失败→修复 |
| 敏感词 | 病名/药物/医院/诊断/自伤 | `test_parse_a_rejects_sensitive`、`test_parse_b_rejects_sensitive` |
| actors 来源 | B 的 actors 只能来自卡文本或助手回复 | `test_actors_come_from_card_or_assistant` |
| cue 来源 | A 的 cue 必须出现在用户原话（scrubbed） | `test_parse_a_rejects_cue_not_in_user_text` |
| 清空 | A 删正文/.bak/.tmp；B 侧栏“清空这张卡的记忆” | `test_clear`、`test_episode_store.test_clear` |

**边界说明**：自动闸门覆盖“自报姓名 + 原文重复 + 敏感词”，不做 NER，不声称能识别对话里顺带提到的所有人名；这与 `memory.scrub` 的既有口径一致。日志只记 `mode=A/B episodes=N`，不记记忆正文。

## 7. 失败与回滚

- 抽取失败/坏 JSON：`mark_try` 后等 5 轮，回复不受影响。
- 写盘失败：只 `logger.warning`；旧文件保留。
- 回滚：去掉 `orchestrator` 的三行调用即可；`memory.json` 与卡文件格式未改；旧版本读不到新目录也不受影响。
- A 的“清空”同时删 `memory.json` 三件套 + `episodes/<sid>.json` 三件套；B 的“重新开始”保留记忆，只有侧栏按钮真删。
