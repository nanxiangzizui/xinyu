# P20 · 聊天帮助模式（2026-11-18）

> 用户 m00002 贴出「引导者」对话截图：问「给点建议」，只回 3 句、约 30 字，没有一条能照着做的具体做法。
> 三条诉求：①查提示词；②字数限制拆成「闲聊 / 帮助」两套；③知识不够时会自动检索、给具体回答。
> 计划见 `docs/v2-steps/P20-chat-modes.md`；本文件记实现、验证与证据。

## 一、根因：不是一个地方，是七道闸门叠在一起

| # | 位置 | 原文 / 行为 | 后果 |
|---|---|---|---|
| 1 | `roles.py:20` | 「回复控制在 3 句以内；对方没有明确求助时，不给建议。」 | 最高优先级的系统段直接写死 3 句 |
| 2 | `agent.py:251` | 「每条回复约 {sentence_len} 字以内」（25 / 30 / 20 / 20 / **15**） | 五张人设卡都是短句设定 |
| 3 | `agent.py:302`（改前） | 只有 `role == "listener"` 有专属段；**guide 什么专属段都没有** | 引导者只继承「短」的规矩，没有「怎么帮」的规矩 |
| 4 | `agent.py:32-35` | 审核 prompt：「超过 4 句」判为不合格 | 第 4 句起就被复核挑出来 |
| 5 | `agent.py:38-41` | 重写 prompt：「3 句以内」 | 真被重写时又压回 3 句 |
| 6 | `style.py:213-224`（改前） | `polish` 统一按 `MAX_CHARS=220` 硬截断 | 450 字的方案会被代码剪掉一半 |
| 7 | `web.py:245`（改前）+ `tools.py:115` | 工具描述「只查专名」；且只在 L1 且 `ALLOW_WEB=1` 才暴露 | 问「睡眠怎么调」时模型没有可调的检索工具 |

关键点：用户截图这一轮 `reason=user_ask_advice`，「给点建议」确实命中 `coordinator.ADVICE_WORDS`（`coordinator.py:8`），角色早就是 guide——**问题不在路由，在 guide 没有任何「放开」的指令，只有七道「收紧」的闸门**。

## 二、改法：模式 = 角色，一套流程两条刻度

不新增节点、不改契约签名：`listener` = 聊天模式，`guide` = 帮助模式，`crisis` 仍然最高优先。

| | 聊天（listener） | 帮助（guide） |
|---|---|---|
| 句数 | ≤3（闲聊）| 4–8 句，最多 8 |
| 字数 | 220 | 460 |
| 结构 | 接住 + 一句 | 一句判断 → 1–3 条动作（时间/动作/量）→ 一句什么时候找真人 |
| guardian 复核 | 句数上限 4 | 句数上限 8 |
| 检索 | 不放开 | `ALLOW_WEB=1` 且 L1 时暴露 `web_search` |
| 触发 | 默认 / 无明确求助 | 命中 `ADVICE_WORDS`（怎么办 / 建议 / 该不该 / 咋办 / 有没有办法 …）或用户手选「引导者」 |

### 3.2 真 key 探针

脚本 `docs/evidence/p20_real_probe_2026-11-18.py`，输出 `docs/evidence/P20-real-probe-2026-11-18.txt`。复现用户场景：先聊失眠，再说「给点建议」。

**帮助模式（guide）**：prompt 1684 字（含帮助段与检索行），回复 **6 句 / 183 字**：

```text
你现在最该做的是今晚把入睡时间往前挪，别指望白天补回来。

1）今晚 23:30 就躺下，手机放到桌子另一头，别带床上。
2）下午三点后不碰咖啡和浓茶，晚饭别吃太撑。
3）明天闹钟固定 7:30，哪怕困也先起来，白天别补觉超过 20 分钟。
4）今天精神差，别硬撑做费脑子的事，先挑轻的做。

要是这样调一周还是睡不好、白天一直没精神，就去校医院或心理中心找真人聊聊
```

对照用户截图那句「先别急着补效率。今晚十一点半躺下，手机放远一点，试试看」：同样是 11 点半，但给了 4 条可执行动作 + 明确的复诊条件，且 6 句没被截断。

**聊天模式（listener）**：prompt 1456 字（无帮助段），回复 **1 句 / 20 字**，无建议、无反问：

```text
昨晚没睡好，今天还撑了一整天，难怪没精神
```

**工具面**：`list_for_turn("guide","L1",allow_web=True)` → `['web_search']`；同角色 `L3` → `[]`（[SAFE] 危机零工具仍然成立）。

**真检索**：问「2026 年杭州马拉松什么时候开始报名」，`tool_calls=1`、`sources=3`、两轮内答完，答案带具体日期，并主动标出没查到的部分（截止日期与抽签）：「建议去杭州马拉松官方微信公众号确认」。

> 证据等级：单次探针 + 用户截图对照，用来说明「行为已改变」，不据此声称任何疗效。

### 3.3 测试锁住了什么

- `test_polish_gives_guide_the_help_limit`：同一段长文，guide 459 字 / listener 219 字。
- `test_help_block_only_for_guide_and_after_the_last_reminder`：guide 才有 `[这一轮：引导者 · 帮助模式]`，且在「最后提醒」之后。
- `test_review_limit_follows_role`：`_review_messages(..., "guide")` 尾部是 `本轮：guide / 句数上限：8`；listener 是 4。
- `test_quiz_block_explains_dims_and_how_to_talk`：`帮我分析` 会切成 guide，帮助段必须让位给「只解释结果，不给动作」。
- `test_sources_render_only_code_filtered_links`：只有代码过滤出的 https 链接会被渲染，模型写的 URL 不进页面。

## 四、已知限制

1. `ALLOW_WEB` 代码默认仍是 0；要联网得在 `.env` / Secrets 显式置 1。侧栏会提示「检索未开」，不会假装查过。
2. 真检索只在 **L1**（`tools.py:115`）；L2 起不联网，避免把情绪升高时的原话发出去。
3. 帮助模式仍有 8 句硬上限；超了会被 guardian 要求重写，这是有意的（防止变成长篇说教）。
4. B 模式（角色卡）未接这套规则，保持 P14 的多段式与短句人设。
5. 探针是单次调用，不是 A/B 统计；「更像人」「更有效」都不在本项目结论范围内。
