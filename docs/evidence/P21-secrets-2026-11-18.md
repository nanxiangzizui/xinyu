# P21 · 开源前密钥与提交包护栏（2026-11-18）

> 用户 m00002（原文）：「这个项目后续会开源并提交源文件交给学校（作业评分），这意味着.env里的apikey会暴露，你有什么建议」
> 做法：先只读取证，再补洞，最后给建议。本文件记取证结论、改动、验证与建议；代码见 `.gitignore` / `.env.example` / `docs/build_package.py` / `tests/test_no_secrets.py`。

## 一、结论先行

**没有泄漏过。** 三条独立证据：

1. `.env` 与 `.streamlit/secrets.toml` 从未被跟踪（含全部分支与 tag 的 58 个 commit）；
2. 取 `.env` 里的真实值逐条 `git grep -F` 全历史，两个 provider key（35 位 / 54 位）命中数都是 0；
3. 全仓文本扫描密钥形状，唯一命中是 `.env.example` 的占位符。

**真正的风险不在"已经泄漏"，而在三条自动化路径：**

| 风险 | 后果 | 本次处理 |
|---|---|---|
| `git add -A` 会带上未忽略的运行时文件（`data/memory/quiz/*.json`、根目录 `p19_*/`、`p16-*/`） | 真实会话结果进仓库 | `.gitignore` 补子目录通配 + `data/**` 兜底 + 探针目录规则 |
| `docs/build_package.py` 停在 v2.0 白名单（17 个模块，漏 24 个 v3 模块） | 打出的包 `app.py` import 失败；**人会改用"直接压缩整个文件夹"，那才会带上 `.env`** | 改成现扫根目录全部 `*.py`，并在落包前自检 |
| `.env.example` 的 `sk-xxxxxxxx…` 形状太像真 key | 被扫描工具/人工复查误判成泄漏，白费一轮排查 | 换成 `sk-your-own-key-here`（20 字符，短于扫描阈值 24） |

一句话：**把"漏"堵上，把"安全路径"修好，再加测试锁死。**

## 三、三处补洞

### 3.1 `.gitignore`（61 → 70 行）

```gitignore
# 趣味测试结果（P13）：落在 data/memory/quiz/ 子目录，上面那条 *.json 匹配不到子目录
data/memory/quiz/*.json
data/memory/quiz/*.bak
data/memory/quiz/*.tmp
# 兜底（P21 开源前自查）：data/ 下任何文件一律不进仓库，将来加子目录不会再漏
data/**
!.gitkeep

# 脚本 mkdtemp(prefix="p19_") / "p16-" 之后留在根目录的临时会话目录
p[0-9][0-9][-_]*/
```

- 原规则只写具体文件通配（`data/memory/*.json` 等），`*` 不跨目录，所以 `data/memory/quiz/1.json` 实测 `git check-ignore` **rc=1**；
- `data/**` 是兜底：以后再加 `data/xxx/` 子目录不会重演；
- `p[0-9][0-9][-_]*/` 一词覆盖 `p19_…` / `p16-…`，也覆盖将来的 `p20_…`；
- 两行 `.gitkeep` 已入库，ignore 不影响已跟踪文件，新克隆仍能带出 `data/memory` 与 `data/logs` 目录。

### 3.2 `.env.example`

```diff
-# 复制为 .env 后填写；.env 不进仓库
+# 复制为 .env 后填写；.env 不进仓库
+# 模型：DeepSeek（OpenAI 兼容接口）
+# 占位符而已：真 key 只写进 .env（不进仓库、不进提交包），别贴到这里
-LLM_API_KEY=旧占位符（24 个 x，此处不逐字复制，否则会被本仓库的扫描规则命中）
+LLM_API_KEY=sk-your-own-key-here
```

占位符从 24 个 `x` 降到 20 个字符，故意短于仓库自检的扫描阈值 24，不会自触发 `test_repo_text_has_no_key_shaped_string`。

### 3.3 `docs/build_package.py`（v2.0 白名单 → 现扫 + 落包自检）

| 项 | 改前 | 改后 |
|---|---|---|
| 源码清单 | `ROOT_FILES` 手写 17 个模块（v2.0 时代） | `_root_modules()` 现扫根目录全部 `*.py`（41 个） |
| 包名 | `心屿-v2.0` | `心屿-v3.0` |
| 材料 | 四份 docx/pptx/mp4/md | 不变（`MATERIALS`） |
| 目录树 | `tests` + `docs/evidence` | 不变（`DIR_TREES`） |
| 自检 | 无 | `_scan_package(pkg) -> list[str]` 三条：禁忌文件/目录名（`.env` / `secrets.toml`）、`data/` 前缀、密钥形状 `KEY_RE` |
| 失败行为 | — | 命中打印 `LEAK <path>` 并 `return 2`，**不生成 zip** |

`KEY_RE = re.compile(r"sk-[A-Za-z0-9]{20,}|tvly-[A-Za-z0-9]{10,}")`；扫描对象是包内**文本文件**（zip 内容先落到临时目录再扫，避免自己解压自己）。

## 四、新增测试 `tests/test_no_secrets.py`（4 条）

| 测试 | 断言 |
|---|---|
| `test_repo_text_has_no_key_shaped_string` | 遍历仓库文本（`SKIP_DIRS` 剪 `.git` / `.venv` / `data` / `真人测试` 等，`TEMP_DIR_RE` 剪探针目录，跳过 `.env` / `secrets.toml` 本身），三条正则（`sk-` / `tvly-` / `(BOCHA\|TAVILY\|LLM\|WEB)_API_KEY=[A-Za-z0-9_-]{24,}`）零命中 |
| `test_secret_and_runtime_files_are_not_tracked` | `git ls-files` 里没有 `.env` / `secrets.toml` / `data/` 下非 `.gitkeep` 文件；无 git 时 `skip` |
| `test_ignore_rules_cover_runtime_paths` | `git check-ignore` 命中 8 条探针路径（`.env`、`secrets.toml`、`data/memory/x.json`、`data/memory/quiz/1.json`、`data/memory/episodes/1.json`、`p19_abcd/logs/x.jsonl`、`p16-aaa/…`、`data/logs/x.jsonl`） |
| `test_packager_refuses_env_data_and_keys` | 用 `importlib.util.spec_from_file_location` 按路径加载打包脚本，对 dirty（含 `.env`）/ leaky（含 `sk-` 32 位）/ clean 三个临时目录分别返回 2 / 1 / 0 个问题 |

设计取舍：

- **不读 `.env`**：测试只读「git 索引」与「仓库文本」，所以放进提交包也能跑，不会因为缺 `.env` 而红；
- **无 git 时 skip**：交作业包解压后没有 `.git`，跳过而不是失败；
- **依赖注入**：打包脚本按路径加载，不需要把它做成包或加 `__init__.py`。

## 六、给用户的建议

### A. 现在就能做（10 分钟）

1. **开源前最后确认一次**：`git log --all -- .env .streamlit/secrets.toml` 应为空；`git ls-files | findstr /i ".env secrets"` 只应出现 `.env.example`。
2. **提交前跑两道**：`pytest tests/test_no_secrets.py -q`、`python docs/build_package.py`；后者打印任何 `LEAK` 就说明包有毒，不要交。
3. **只交 zip**：学校要"源文件"时交 `build_package.py` 打出的包，不要交整个文件夹（文件夹里一定有 `.env` 与 `data/`）。

### B. key 本身

4. **作废重建的条件**：只要这把 key 曾出现在聊天记录、群、文档、截图、录屏里，就去 DeepSeek 控制台**作废并新建**——与仓库是否泄漏无关，截图比仓库更容易流传。
5. **本地一把、线上一把**：本地 `.env` 与 Streamlit Cloud Secrets 用不同的 key；撤销线上那把不影响你在本机 300 秒录屏。
6. **设消费上限**：DeepSeek 控制台可设预算；博查 / Tavily 同理。这是"即使泄漏也不会被刷爆"的最后一道。
7. **开源后的默认姿势**：仓库里只放 `.env.example`；评委/同学不需要你的 key 也能跑——`MOCK_LLM=1` 是完整离线演示路径。

### C. 建立习惯（可选）

8. 每次 `git add` 前扫一眼 `git status --porcelain`：`.env` 不该出现在任何列表里（出现即说明 ignore 坏了）。
9. 想更硬一点可以加纯 git `pre-commit` 钩子（不引入依赖），但会拖慢提交，本轮没做。

### D. 万一将来真的泄漏了

10. 顺序：**先作废 key（控制台）→ 再改代码/配置 → 最后才考虑清理历史**。作废永远比洗历史便宜；只有确定会公开且必须公开历史时才需要 `git filter-repo`。
