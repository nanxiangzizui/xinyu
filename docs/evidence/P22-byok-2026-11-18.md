# P22 · 访客自带 Key（BYOK）· 2026-11-18

## 一、结论先行

侧栏新增「模型设置（可选）」：访客填自己的 DeepSeek Key，就按访客自己的额度走；不填或点「清除」，立刻回到站点额度。

站点也没有 Key 时，页面不再整页报错，而是打开「演示模式」横幅：页面能进、回复由本地脚本生成、危机路径（L3）照常零 LLM 出模板与资源卡。

**只收 Key，不收 base_url；模型名写死 `deepseek-chat`；Key 只进 `st.session_state`，不落盘、不写日志、不进 prompt / memory / trace。**

## 二、用户决策

- 用户 m00263 原话：「要不在线上加一个用户自己配置模型的端口？」
- 用户 m00266 原话：「先按你推荐用A」

A 方案 = 线上默认用站点演示 Key + 侧栏允许访客自带 Key。与 B 方案（默认 MOCK、要真聊必须填自己的 Key）相比，A 让打开就能聊，B 更省钱但演示体验差；课程演示期选 A。

## 三、设计选择与理由

| 选择 | 理由 |
|---|---|
| 只收 Key，不收 base_url | 服务端替访客请求任意地址等于开放 SSRF，也违反项目「工具不接受任意 URL」红线；固定发 `api.deepseek.com` |
| 模型名写死 | 访客换模型会绕开我们调过的 prompt 与句数规则，行为不可控 |
| Key 只进 `session_state` | 刷新即失效，进程里不落盘；不写进 `memory.json` / JSONL / trace / prompt |
| `agent` 用 `ContextVar` 存会话 Key | 两个浏览器会话各跑各的线程；模块级变量会让 A 的 Key 发 B 的话 |
| 访客 Key 的 client 不缓存 | 缓存等于把别人的 Key 留在进程里，还可能串用连接；站点 Key 仍懒加载复用 |
| 缺 Key 不在 `call_llm` 里转 mock | `tests/test_agent.py::test_missing_key_raises_runtime_error` 的契约要保住；演示模式由 app 层显式打开（`agent.set_demo_mode(True)`） |
| 演示模式横幅而非 `st.stop()` | 站点初次部署 / Secrets 掉了时页面能开，至少能看到界面与危机资源 |

## 五、测试（13 条）

1. `valid` 接受 `sk-` 形状，拒绝空串 / 太短 / `tvly-` / 超长
2. `clean` 去空白与引号
3. `set_key` / `clear` 往返
4. 非法 Key 不覆盖原值
5. `set_key` 不写环境变量
6. `mode_label` 三态（自己的 / 站点 / 演示）
7. `call_llm` 使用会话 Key（monkeypatch `_get_client` 断言收到的 Key）
8. `chat_with_tools` 使用会话 Key
9. 演示模式返回 `agent.MOCK_LINES`
10. 既无 Key 也未开演示 → 仍 `RuntimeError`
11. AppTest：无 Key 时出现「演示模式」横幅，且侧栏有「DeepSeek API Key」输入框
12. AppTest：填 Key 点「使用这个 Key」后 `session_state["byok_key"]` 写入、横幅消失
13. AppTest：点「清除」后回到演示模式
