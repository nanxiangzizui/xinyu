# P23b · 情境示例与建卡示例（2026-11-20）

> 接着 P23（风格层）之后做的两件事：① A 模式按情境给示例 ② 建卡页自动生成示例对话。
> 结论先说：**①改了两次才成立——给成品句会被五个人设照抄，最后只给"对方上一句 + 该做什么"**；
> **②一次成立，6 组候选都像卡里那个人**。

## 一、为什么做

P23 把 A 模式的两条正向规则（接原词 / 落到具体）立住了，但示例层还是只有
`roles.LIVE_EXAMPLES` 的 2 条边界示例（"你是真人吗" / "我说重了"）。用户提到的问题里，
「AI 味太重」不只出在规则，也出在「这个情境下这个角色会怎么开口」没有示范。

B 模式（角色卡）的问题更直接：卡上的两组示例要用户自己想，写不好整张卡就没人味。

## 二、① 情境示例：两次失败 + 一次成立

表在 `examples.py:SITUATIONS`：12 个情境 × 5 人设，共 60 句，都 ≤40 字。

| 版本 | 拼进 prompt 的内容 | 五人设首句 | 结论 |
|---|---|---|---|
| v1 | `用户：今天有点累，什么都不想干` / `你：{该人设的成品句}` | **4/5 与示例逐字相同** | 不可用：每句日常话都变成同一句罐头 |
| v2 | v1 + `（只学这一句的口气，不要照抄…）` | 2/5 逐字相同 | 不够：加在示例后面的禁令压不住示例 |
| v3（终版） | `对方上一句：…` + `（先接住这一句里的那个词，再落一件具体的小事；不问为什么，也不劝。）` | **0/5 照抄，5/5 互不相同** | 采用 |

v3 真 key 五个人设的输出（同为「今天有点累，什么都不想干」）：

```text
sister_heart:    那就先什么都别干。累的时候，躺着也是正事。
warm_senpai:     累的时候就先别干。手边有杯水吗，先喝一口。
rational_mentor: 累就歇着吧。有件小事能顺手做就做，做不了就放着。
energy_buddy:    那就先什么都不干吧。累的时候瘫着也是正经事。
quiet_hollow:    嗯，累就先歇着。
```

这就是 P23 那条教训的第二次验证：**示例比规则更会带节奏**，而位置比措辞更管用——
把"不要照抄"放在成品句前面，模型照抄；把成品句拿掉，模型就只能借口气。

### 线索为什么要收紧

第一版 `tired` 的线索是单字「累」，`最近在积累经验` 会被判成累；
`anxious` 的「慌」同理。改成词组后（`好累 / 很累 / 累了 / 累到 / 心累`、`心慌 / 很慌 / 慌得`），
`tests/test_examples.py::test_tag_of_returns_empty_for_smalltalk` 锁住两条反例。

判断在哪：`examples.tag_of(text)` 是纯函数，只做关键词命中，认不出来返回空串，不猜。
接线的三处：

| 文件 | 改动 | 为什么在这 |
|---|---|---|
| `orchestrator.py:207` | `facts["_role"], facts["_situation"] = dec["role"], examples.tag_of(text)` | 只有这层有本轮原话；同一行写两个字段是为了守住 250 行 |
| `agent.py:295-297` | `_style_block(..., situation="")` 里追加 `examples.situational(persona, situation)` | 风格区在事实区之前，示例属于"怎么说话" |
| `examples.py` | `SITUATIONS` / `tag_of` / `situational` | roles / style 都已到 350 行硬顶，只能单开文件 |

`_situation` 只活在 facts 里，不写 memory.json、不进日志、不进 trace。

## 三、② 建卡示例：6 组候选，挑一组填进去

`examples.card_candidates(card)` → 6 组 `(user, role)`：

- 只读卡上"怎么开口"有关的字段（名称 / 身份 / 设定 / 口吻 / 称呼 / 对方是谁 / 禁忌），不带聊天记录；
- 6 个情境：初见 / 说累 / 只回「嗯」/ 分享开心的事 / 问是不是真人 / 道谢要走；
- 每一条都要过闸门：非空、`rolecard.EXAMPLE_USER_MAX`（60）/ `EXAMPLE_ROLE_MAX`（100）以内、
  不含「建议你 / 你可以试试 / 应该 / 必须 / 抑郁 / 自杀…」、不含卡上的禁忌句、user 句去重；
- 模型失败、输出不是数组、卡上没身份没设定：返回空列表，UI 不报错、不编造；
- 演示模式（MOCK）走本地脚本，同样返回空——**宁可空着，也不给假对话**。

真 key，虚构卡「守夜人」（话少、短句、偶尔提天气或灯）：

```text
用户：你好，第一次见。       角色：嗯。风大，站这边。
用户：今天真的很累。         角色：灯还亮着。坐会儿吧。
用户：嗯。                   角色：嗯。海那边起雾了。
用户：今天有件特别开心的事。 角色：说来听听。灯正好稳。
用户：你是真人吗？           角色：是。手是凉的，灯是热的。
用户：谢谢你，我先走了。     角色：路滑。灯给你照着。
```

界面：建卡表单「两组示例对话」下面一个按钮「让心屿先写 6 组示例」，
生成后一个下拉框 + 两个按钮「填到示例 1 / 2」。填进去之后用户仍可改——
这一层只给起点，不替用户定稿。回调 `_fill_example` 走 `on_click`，
因为直接在渲染里改控件状态会撞 Streamlit 的「控件已实例化」。

## 六、已知限制

1. 12 个情境是"日常可预期"的一小撮，长对话里的复合情境（比如又累又慌）只取最靠前的一个；
2. `tag_of` 是关键词法，认不出就静默跳过——宁可少给，不给错的；
3. ② 的 6 组来自一次调用，没有做"再写一批"的翻页；不满意可以点第二次；
4. ① 只接 A 模式；B 模式的示例由用户在建卡页决定（②就是为这件事准备的）。
