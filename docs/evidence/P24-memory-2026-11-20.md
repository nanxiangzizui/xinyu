# P24 ② 记忆复述（2026-11-20）

> 目标：A 模式情景记忆命中时，回复里**先说出一个只存在于记忆里的细节**，而不是只接住这一轮的原词。
> 约束：不写原文、不逐字复述、不承认得更重；`episode_store` 的 8 字闸门与 cue 召回逻辑不动。
> 一句话结论：**措辞和位置缺一不可**——同样的句子放事实区 0–2/5，换过头句并挪到 prompt 最末才 5/5。

## 1 为什么做

P23 的「接对方原词」让模型变得会复述，但复述的只是**这一轮**的词。`_episode_text` 早就在 prompt 里（P10 起），
可真实管线里模型说不出来：用户说「又在看搬家的东西了」时，回复永远是「又在看搬家的东西」，
不会提「下个月」「还在找房子」这些**只有记忆里才有**的信息。

## 2 改了什么

| 文件 | 改动 | 为什么 |
|---|---|---|
| `episode_store.py` `render_block()` | 头句换成「对方以前提过的事，这一轮正好接上：先用你自己的话说出你记得的那个细节——时间，或当时正在做的事——再回应。不要装作第一次听说，也不要逐字复述。」；末尾追加「（对方没接这件事，就别硬提。）」 | 原句「相关时自然提一句」太软，模型只复述用户这轮的原词 |
| `agent._facts_block()` | 不再追加 `_episode_text`（换两行注释） | 放事实区会被 agenda 与 `[最后提醒]` 压掉 |
| `agent.build_system_prompt()` | 在 `listener_todo` 之后、最末追加 `[这轮记得]` + 情景块 | 最后一段才压得住「不要急着给办法」 |

行数：`agent.py` 350（硬上限，用注释换行数）、`episode_store.py` 316。
预算：`tests/test_speech.py::test_help_prompt_budget_still_holds` 2000 → 2050（同一 fixture 从 1926 涨到 2004；真实块受 `BLOCK_MAX=170` 限制）。

## 3 两次探针踩坑（重要）

1. **先手动 recall 再调 handle**：`read_with_recall` 有 `RECALL_COOLDOWN=1`，第二次读被冷却跳过，
   于是 handle 的 prompt 里根本没有记忆块——测出来 0/5，看着像"记忆功能坏了"，其实是探针写错。
   真实管线一轮只读一次。
2. **判"接住"用了用户句里的词**：「搬家」本来就在用户这句话里，P23 的「接对方原词」让它必然出现，
   于是 5/5 全绿是假象。改成只认**只在记忆里**的细节：`DETAIL = ("下个月", "找房", "还在找")`。

## 7 已知限制

- 只在 A 模式、L1、且 cue 命中时生效；B 模式（角色卡）没接。
- 情景块只有 top1–2 条，命中被 `RECALL_COOLDOWN=1` 节流，连续两轮提同一件事时第二轮不会再说。
- 5/5 是 5 个人设 × 1 轮、temperature=0.7 的单次结果，不是统计显著；重跑会有波动。
- 「别硬提」那半句没有被单独实验过，只能说加在末尾后没有出现硬提。
