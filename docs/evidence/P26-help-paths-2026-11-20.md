# P26 危机下一步 / 朋友出事 / 能力边界（2026-11-20）

## 一、为什么做这一条

学校评分口径变了：技术力不再是重点加分项，"能解决多少现实问题"才是。
按这个口径重看心屿，问题地图有五格，P0–P25 只把中间一格做满：

| 格 | 现实里的样子 | 心屿原来的状态 |
|---|---|---|
| 进不来 | 说不出口、怕被记录、不知道能干嘛 | 有首屏 12 项，但没回答"它是什么、记了什么" |
| 说不清 | 只发一句"难受"、只发一个"？" | 有 P23/P25 的口语层，但没有"此刻下一步" |
| 说完就断 | 说完之后没有下文 | 记忆只在用户自己提起时用 |
| **身边的人** | 朋友说"不想活了"，自己不知道说什么 | `guardian.py` 里"朋友 / 室友"零命中：系统默认当事人=用户 |
| **机构接不住** | 只给三个号码，深夜打校中心没人接 | L3 固定三张资源卡，没有时段分流与话术 |

本轮只做第一天的三件（T1 / T2 / T6），全部落在**静态内容层**：
不碰判定逻辑、不加红线、不调模型。改动后 `guardian` / `RULES` / `coordinator` /
`memory` 白名单 / `orchestrator` 一步没动，契约仍是 11/5/20。

## 三、两道坑（都写进了代码注释）

### 3.1 "下一步"不能画在 `extra()` 里

`_run_turn` 的 `extra()` 只在本轮渲染回复时调用一次；下一帧重绘走
`render_history`，那块按钮根本不存在。于是点击"看完整的求助页"时，
浏览器带着 `help_open_chat=True` 重跑脚本，脚本却没画这个按钮，
**点击被直接丢掉**（探针 `_p26_probe2.py` 点完 `mode` 仍是 `companion`，
按钮也从元素树消失）。

改成在 `render()` 里、`_turn(sid)` 之后画。依据 Streamlit 源码
`streamlit/elements/widgets/chat.py:1082-1097`：`st.chat_input` 会被自动移进
底部容器（`is_auto_positioned_at_bottom`），**之后创建的元素仍在主滚动区**，
所以画在它后面不是"塞到输入框底下"，而是消息流末尾、输入框上方。
每帧都画 → 按钮每帧都在 → 第二次点击也有效。

### 3.2 AppTest 的 multiselect 要传原始值

页面里 `st.multiselect(..., list(OPTIONS), format_func=OPTIONS.get, key=...)`，
选项的原始值是 `memory/episodes/quiz`，显示是中文。测试里写
`select(OPTIONS["memory"])`（中文标签）时，标签被塞进原始值列表，
`format_func` 对它返回 `None`，Streamlit 在
`element_tree.py:2490` 的 `ws.string_array_value.data[:] = self.values`
抛 `TypeError: bad argument type for built-in operation`。
正确写法是 `select("memory")`（原始值）；`values` / `options` 才是格式化后的。
探针 `_p26_probe3.py` 记录了 `select(0)` / `set_value([0])` / `select(标签)`
在纯 index 选项下的差异。

另：`_back()` 一开始总会画"回首页"，与侧栏 `home_back` 重复。
改成只在 `HOME_HUB=0`（侧栏没有返回键）时补一个，且回 `companion`。

## 五、已知限制（答辩时说清楚，不算缺陷）

- 只按**时段**分流，不按情绪与紧急程度分流；校中心 8–17 是硬编码，值班主任表不进运行时。
