# P29 写下来接一句 + 咨询前后两张卡（T4 / T5，2026-11-20）

## 一、为什么做

P26–P28 补的是「进不来」这一端（分诊、求助页、对抗集）。这条链路还剩下两个断点：

| 现实问题 | 现状 | 这次补什么 |
|---|---|---|
| 写了没人应 | 「写下来」写完只有一张空白和「撕掉」，像对着墙说话 | 写过之后页面回一句固定的话，并给一个「回聊天」的口 |
| 第一次去咨询不知道说什么 | 站内只有「危机」和「朋友」两种求助页，没有「还没到危机、但要见人」的准备页 | 咨询前准备页：怎么开口、带什么、会被问什么、可以拒绝什么 |
| 见完咨询师那一周没人管 | 站内没有「见完之后」的内容，用户容易把「没有立刻变好」理解成失败 | 咨询后一周页：常见反应、先做一件小事、什么时候再约、不合适怎么办 |

这两块都是**纯静态内容 + 路由**：不调模型、不判级、不写记忆、不联网，所以不需要真 key 探针。

## 三、设计取舍

1. **不回显用户写的内容**：页面只回固定句，不引用、不摘要、不评价。写下来的语义是「倒出来」，不是「交作业」。
2. **不加「保存」按钮**：现有契约是只放 session，刷新即没；这次没有把内容写进任何文件，也没有新增存储。
3. **咨询后页给了「危险时指回求助页」**：那一周如果出现伤害自己的想法，页尾直接把用户送回「我现在很难受」，而不是自己再列一遍号码——号码只在资源卡与求助页出现一次，少一处漂移。
4. **不用「咨询会有用」的承诺**：文案只说流程与常见反应，不说效果；这符合术语红线「不声称疗效」。
5. **不新增文件**：两张卡塞进 `help_pages.py`（195 行），避免第四次破「不再加文件」的例外。

新增/修改的测试点：

1. 空内容时没有回应；写一句后出现 `JOURNAL_ACK` 与 `JOURNAL_NEXT`；页面其它位置不出现用户写的那句话。
2. 「撕掉」后回应消失（内容清空）。
3. 「回聊天，接着说」切到 `companion` 并出现 `chat_input`。
4. 首页 → 咨询前页：`mode=help`、`help_page=before`、无 `chat_input`、含「不知道怎么开口」「可以拒绝回答」与校心理中心电话。
5. 首页 → 咨询后页：含「有点空」「什么时候再约」「如果这次不合适」，并把危险情况指回「我现在很难受」。
6. 两张卡都不写日志（`rows(sid)` 前后不变）。

## 五、已知限制

- 两张卡是通用内容，不含各学院/各校区的具体预约流程；具体入口仍以首页资源卡与校心理中心电话为准。
- 「回聊天，接着说」只把模式切到聊天，不替用户组织第一句话（开场问答与聊天入口已承担这件事）。
- 咨询后的「什么时候再约」是经验性判断，不是临床标准；页面没有给出量化阈值。
- 写下来页仍不保存，刷新即丢；这次没有改变这一点，也没有加「导出」。
