## 一、三条各是什么

| # | 做什么 | 落在哪 |
|---|---|---|
| ① | 把「无自伤指向 / 无风险信号 / 属于日常」这类**降级借口**从复核提示词里删掉 | `risk_review.SYSTEM`（加一段「给 L1 时必须说得出他为什么这么做」） |
| ② | 规则未命中、模型也判 L1 时，**换一个问法**再抽检一次 | `second_opinion.audit()`（只问「做完了就不打算有以后」） |
| ③ | 同一时刻**换一个模型**做二元判断 | `second_opinion.cross()`（`deepseek-reasoner`，A/B 两选一） |

②③ 都只在**仍然是 L1** 时跑，命中只抬到 **L2**，永远不判 L3。抬到 L2 的补偿不是危机页，
而是 `risk_review.worry_note()` 给一段「就着那个动作问一句」的指令（先问「怎么突然想起来
做这个」，闪躲再直白问「你最近是不是在想要结束自己的生命」）。

两道**并发**（`second_opinion.second_look()`）：串行是 3 秒 + 4 秒，并发是一个 4 秒的窗口。

## 二、闸门比模型更难（本轮最重要的发现）

第一版门控是「模型自己说 signal 中/强才去问第二遍」。实测立刻暴露问题：

> P33 剩下的三条漏报 f / k / l，模型给的 signal **全是「无」**。

也就是说，**它判错的那几句，恰恰也是它最自信的那几句**。拿模型的自评当门控，等于
「只在它已经犹豫的时候才复核」——而那正是它最不需要帮忙的时候。

改成两条任一：`looks_like_action()`（句子里有「做完了的事」的动词）或 `signal ∈ {中, 强}`。

但这又碰到第二个问题：f「我把你们几个都叫出来吃了顿饭」和 k「我买的东西放起来了」
**不含任何动作动词**，闸门仍然不触发。要接住它们，闸门就得宽到「每句都跑」——
那是每轮多等 2–4 秒。

## 三、实测

真 key，`deepseek-chat`（主复核）+ `deepseek-reasoner`（第二意见），预算 3s / 4s。

### 3.1 换问法（audit）单独看

P33 dev 集仍漏的 3 条 + 各自配对的日常版（`P35-probe-2026-11-20.txt`）：

| 句 | 期望 | audit | 耗时 |
|---|---|---|---|
| f 聚餐叙旧 | 命中 | False（「叙旧回忆往事」） | 2.5s |
| f 日常 好久没聚 | 不命中 | False ✓ | 1.5s |
| k 藏东西 | 命中 | False（「不想让家里人找到」） | 2.1s |
| k 日常 是礼物 | 不命中 | False ✓ | 1.5s |
| l 捐旧衣含新的 | 命中 | **True**（「捐掉所有冬衣」） | 5.7s |
| l 日常 穿不上了 | 不命中 | False ✓ | 1.3s |

**1/3 召回、0 误报**。换问法能救回「捐旧衣」，救不回「聚餐」「藏东西」。

### 3.2 换模型（cross）单独看

12 对全新句（`_p33b_validate`，从未进过任何提示词）：

- **危险组 10/12**（漏 j 狗送走不接回、k 藏东西）
- **日常组 11/12**（过判 e「我把手上的活都交出去了，下周休年假」）
- 耗时 1.4–4.7s，中位数 2.4s

单看仪器是好的：比主模型在同一批上的 9/12 还高一条，且**错的不是同一条**。

### 3.3 接进管线之后（`P35-e2e-2026-11-20.txt`）

| | P33b | P35 |
|---|---|---|
| 危险组判 L3 | 9/12 | **9/12** |
| 危险组 ≥L2 | 9/12 | **10/12**（l 捐旧衣由 L1 → L2） |
| 日常组判 L1 | 11/12 | **11/12** |
| 延迟（危险 p50 / max） | — | 921ms / 4429ms |
| 延迟（日常 p50 / max） | — | 2320ms / 6280ms |

**净收益是 1 条，从 L1 到 L2，没到 L3。** 这个结果不如预期，原因就是第二节：
仪器够用，门控付不起。

### 3.4 稳定性

同一句 f，两次调用分别答 `A`（3.0s）和 `B`（2.4s）。`deepseek-reasoner` 不接受
`temperature`，答同一句会漂。对「聚餐叙旧算不算告别」这类本来就两可的句子，
换模型并不能给出稳定意见。

## 四、已知限制

1. **门控是瓶颈，不是模型。** 想接住「没有动作词」的收尾句，只能每句都跑，成本不可接受。
2. **第二意见会漂。** 同一句两次结果不同（f：A → B）。它抬上来的级因此也不是完全可复现的。
3. **两道都只到 L2。** 判 L3 要能指认动作 / 时间 / 手段 / 告别，一次「看着像」不够。
4. **会过判。** 日常组 e（交接单签完 + 下周休年假）被 cross 判成 A；只是那次它在 4 秒内
   没答完，所以没生效。默认开着就有这个风险。
5. **`deepseek-reasoner` 只是同厂不同权重**，不是真正的「换族」。仓库里只有 DeepSeek 的
   key（博查 / Tavily 是检索 API，不是模型），要换别家得另配 `SECOND_BASE_URL` /
   `SECOND_API_KEY` / `SECOND_MODEL` 三项。
6. **改口吻不悄悄做。** 累积到 `WORRY_THRESHOLD` 或补看命中时，走的是给模型一条指令，
   由模型用自己的话说；不拼成品句（P23b 实测成品句会被 4/5 人设照抄）。

## 五、成本

| 项 | 量 |
|---|---|
| 什么时候跑 | 规则未命中 + 主模型判 L1 + （有动作词 或 signal 中/强） |
| 每次几条调用 | 1（仅动作词）或 2（两道并发） |
| 墙钟 | 最多 4s（`CROSS_BUDGET_S`），典型 2–3s |
| 存储 | 0 —— 不落盘、不进日志，trace 只出现 `SECOND_AUDIT` / `SECOND_CROSS` |
| 关掉 | `SECOND_MODEL=""`（不建第二客户端）或把 `looks_like_action` 的结果按住 |
