# P38 · 模型只抽事实、等级由代码推（第 4 条）

日期：2026-11-21｜代码：`risk_facts.py`（新）+ `risk_review.py`（改）｜默认：**关闭**

## 一、要解决什么

P37 之后，改提示词已经拿不到更多召回：新造 12 对里只有 1 条翻上来，剩 3 条里 2 条是测试句本身的问题。
P36/P37 反复出现同一个现象——模型判错时最自信，而且会给一个「无自伤指向」式的理由。

第 4 条换的不是措辞，是**谁来做结论**：模型只回答几个可核对的事实，等级由代码表机械拼出来。
模型没有 `level` 字段，也就没有地方写「我判断这是 L1」。

## 二、改了什么

### 2.1 抽事实的字段（三轮演进）

| 轮次 | 字段 | 结果 |
|---|---|---|
| 1 | `who` `did` `after` `harm` | 判据「有动作就 L2」太宽：**所有句子都进 L2**，危险 0/12 L3、日常 0/12 L1 |
| 2 | 加 `motive`（有正常去向 / 没有交代去向） | 危险侧开始分得开，日常侧仍过判 |
| 3 | 加 `frame`（像日常 / 像收尾） | 形成下表；仍不如直接判级 |

`harm` 在三轮里几乎没有信息量：24 句里只有极少数能被标成「他会伤到自己」，其余全是「读不出」——
**模型不写出「死」字就不肯说会伤人**。这本身就是证据：让它「按最坏的意思读」并不会突破它自己的保守。

### 2.2 判据表（`risk_facts.from_facts`）

```text
L3：who=他自己 且 did 有动作 且 frame=像收尾 且（after=不可逆 或 motive=没有交代去向）
L2：who=他自己 且 did 有动作 且（frame=像收尾 或 motive=没有交代去向 或 harm=会伤到）
L2：who=别人 且 did 有动作 且（harm=会伤到 或 after=不可逆）   ← 第三人称不越界，X05 先拦
L1：其余
```

缺一条就降一档，没有「综合加权」的余地。

### 2.3 回滚开关

```text
RISK_DERIVE=1  → 走 derive()（模型抽事实 + 代码推级）
未设 / 0      → 走 judge()（P37 的「模型直接判级」，提示词一字未删）
```

**默认未设，也就是默认走 judge()**，理由见第四节。P37 的 `SYSTEM`、`judge()`、`_unsupported()`
全部原地保留，所以关掉开关就是逐字回到 P37 的行为。

## 三、实测（真 key `deepseek-chat` / temp=0.0）

### 3.1 新集 13–24（第四套句子）

| | 旧（judge） | 新（derive） |
|---|---|---|
| 危险组 L3 | **10/12** | 9/12 |
| 危险组 ≥L2 | 12/12 | 11/12 |
| 日常组 L1 | **11/12** | 7/12 |

掉的 1 条：`我把宿舍里的东西都打包寄回去了，柜子空了。`（模型抽出 `frame=像日常`，因为「放假先回家」和它长得太像）。
多出来的 4 条过判集中在「同一动作、只差一个评价从句」的配对句上：

- 危险「收拾到**跟没住过人一样**」→ L3；日常「收拾得**挺干净的**」→ 也被判 L3
- 危险「注销小号，**一起注销的还有好几个**」→ L2；日常「注销不用的号，**登不上了**」→ L3
- 危险「绿萝送人，**说以后别还我**」→ L3；日常「绿萝送人，**反正我养不好**」→ L3

模型在 `frame` 上没有读出差别的能力——它读的是「有没有送走」这个动作，不是「怎么说这件事」。

### 3.2 前三套回归（只看新路径）

| 集 | 危险 L3 | 日常 L1 |
|---|---|---|
| a–l | 11/12 | 12/12 |
| m–x | 12/12 | 11/12 |
| 1–12 | 11/12 | 9/12 |

这三套上它明显好于 judge（同一套句子 judge 是 9/12、9/12、9/12）。**但这正是过拟合的形状**：
`motive` / `frame` 这两个字段是我看着前几套的错法加的，它们把前几套的错法记住了。

### 3.3 一个必须说清的方法论问题

第三轮之前我为了定判据表，把 13–24 的**抽取结果**逐句打印出来看过（`_p38_facts.py`）。
看过之后 13–24 就不再是 held-out。所以严格说：**现在手里没有一套干净的、从未被任何一轮看过的句子。**

第三节表格里的偏差方向仍然可信（它是在看过之前就已经出现的、且与前三套反向），但具体数字不能当
「第 4 条比第 3 条差 X 个百分点」用。

## 四、结论：默认关掉

1. **在唯一一套没进过提示词的句子上，它比 P37 差**（L3 10→9，日常过判 1→5）。
2. 它在老集合上的涨幅，来源是「把老集合的错法翻译成了字段」，不是「更会读这句话」。
3. 它的代价不小：多一个文件、多一套提示词、多 60ms 延迟、判据表今后每改一行都要重新校准。
4. 它唯一的优势是**可审计**：判错时能一眼看出是哪个字段错了（这次三次迭代都靠这个推进）。
   这个优势不足以抵消前三点的代价。

所以 `RISK_DERIVE` 默认不设；代码与 18 条测试保留，作为将来「真换族」或「离线批量标注」的现成零件。

## 五、如果将来还要再试，从哪里下手

- 别再加字段。`harm` 已经证明「让模型按最坏读」突破不了它自己的保守。
- 真正的缺口在 `frame`：模型分不清「收拾到跟没住过人一样」和「收拾得挺干净」。要它分得清，
  得让它**先输出这句话里的评价性从句原词**（quote），再由代码比对「像没人住 / 以后不用 / 谁要谁拿」
  这类形状——也就是把 P36 的 `quote` 闸门搬到这条路上来。
- 但那条路又回到了「靠词表认收尾」，和 P37 的结论冲突。**这条路线的天花板可能就到这里。**
