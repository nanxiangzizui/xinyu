## 二、线上那次 `ImportError`（已修）

发布后首次访问，站点只有红色错误框：

```
ImportError: This app has encountered an error. …
Traceback:
File "/mount/src/xinyu/app.py", line 46, in <module>
    from ui_common import (DEFAULT_PERSONA, DISCLAIMER, back_button, get_session_id,
```

排查过程：

1. **先排仓库**：`git worktree add … 46203fd` 后 `MOCK_LLM=1 python -c "import app"` → `APP IMPORT OK`，说明同一提交在本地干净检出可导入；`pytest` 828 passed。
2. **再排入口**：v3.2 的 `app.py` 第 46 行没有 `back_button` / `nav_record` / `talk_button`（那是 P41 / P42 才加的），线上报错的源码行与 v3.3 一致 → 线上跑的是新 `app.py`，但容器里的 `ui_common.py` 还是旧版本（旧文件没有 `talk_button`，于是 `from ui_common import …` 失败）。
3. **试了两次自动重建都没用**：空提交 `def0c1c`、真实文件改动 `bcbee74`，各轮询 18 × 15 秒仍是同一个错误 → Streamlit Cloud 这次的同步没有真正替换 `ui_common.py`（与本地一度出现的 `unable to unlink old 'docs/01_项目文档.docx'` 属同一类「旧文件没被替换」）。
4. **最后用「真实文件变更 + 依赖文件变更」逼完整重建**：`905180c` 同时改 `ui_common.py`（文件头加一行标记注释）与 `requirements.txt`（尾部加一行注释）→ 15 秒内站点恢复。

一句话经验：**Streamlit Cloud 上如果出现「新文件生效、旧文件没换」的导入错误，空提交不管用；要改一个被导入的文件本身（或 requirements.txt）逼它重新拉取，再不行才是后台 Reboot。**
