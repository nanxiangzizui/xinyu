## 3 接口与顺序

~~~text
style.polish(text: str, persona: str = "", level: str = "L1") -> str
style.tone_hint(persona: str) -> str
~~~

- polish 顺序：_clip（超 220 才截，优先句末标点）→ _strip_period（只去末尾一个「。」）→ _sticker（只 L1，且已有同款不加）。
- L3 或空文本直接原样返回；本模块不调用模型、不读记忆、不写日志。
- orchestrator 调用条件（[SAFE]，四条同时满足）：
  post["pass"] and not post.get("template_fallback") and eff_level != "L3" and reply != FALLBACK_LINE
- 为什么加第四条：FALLBACK_LINE 是故障兜底句，必须逐字保留并维持 degraded 语义；文档只写三条件，这是唯一功能性偏差。
- agent._style_block 末尾追加 "\n" + tone_hint(persona)；build_system_prompt 对未知人设先回退 sister_heart，保证 unknown 与默认人设 prompt 一致。

## 7 与文档的偏差

1. 文档 test_template_fallback_text_is_untouched 直接对 SAFE_FALLBACK 调 polish；polish 对 L2 会去句尾句号，该用例必红且与设计冲突。改为编排层强制 template_fallback，并 monkeypatch polish 抛错，断言原文逐字。
2. 文档 test_clip_happens_at_sentence_end 期望 polish 输出以「。」结尾；实际 polish 截断后再去句号。改为断言 style._clip(body) 以「。」结尾且 ≤220，polish 输出不以「。」结尾。
3. 文档 _style_block(persona) 示例与实际不符；实际签名为 (p: dict, persona_id: str)，末尾追加 hint。
4. 未知人设若直接传 persona_id 给 tone_hint，unknown 与 sister_heart prompt 不等，test_roles 会红；改为 persona_key 先回退。
5. 增加 reply != FALLBACK_LINE 第四条件（见 §3）。
6. style.py docstring 避免“诊断”二字，以过 P5 文档 §7 #9 的禁用词 grep。
