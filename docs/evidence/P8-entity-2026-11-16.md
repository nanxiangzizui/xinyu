# P8a 证据：专名识别 + 接话（2026-11-16）

> 任务来源：`真人测试.txt`。用户问「你知道昔涟吗」，旧版停在「我不太确定你说的昔涟是谁」，
> 下一轮用户已经把「她」当成理想化对象在说，agent 却还在问「她是谁」。
> 本阶段只解决一件事：**用户提到一个模型不认识的名字时，agent 能接住话题，而不是把话题打回原点。**

## 1. 结论

- 采用用户选定的 C 方案：**接话规则（覆盖所有未知专名）+ 本地词条卡（预置昔涟）+ 网络检索（P8b 已接通：中文博查 / 英文 Tavily）**。
- 优先级：规则 > 本地卡 > 网络。理由是规则不依赖任何外部数据，卡只解决高价值个案，网络通用但需要 provider/key。
- 真实 key 四轮 smoke 已跑通：t1 认出、t2/t3 接住理想化、t4 落 L2 且不反问。
- **219 passed**；契约 11/11 + 5/5 + 20/20；四指标 10/10、0/20、12/12、10/10；五人设 prompt 最坏 **1197/1200**。
- **P8a + P8b 完成**。P8b 已接通真实检索：中文 / ACG → 博查，英文 / 技术 → Tavily；本地 `.env` 已配 key（不入库），`ALLOW_WEB=1` 仅供本地，模板默认 0。

## 2. 探针：模型原本不认识昔涟

真实 key、`temperature=0`，探针文件：

- `docs/evidence/probes/_probe_xilian_2026-11-16.py` / `.txt`
- `docs/evidence/probes/_probe_xilian_rules_2026-11-16.py` / `.txt`

| 条件 | 问「你知道昔涟吗」的回复 | 判断 |
|---|---|---|
| 裸问 | 不太确定，你说的是哪里的昔涟？ | 模型权重不认识（HSR 3.7，2025-11-05） |
| 正式 system prompt | 不太确定，你说的是哪里的昔涟？ | 旧 prompt 只教「承认不知道」，不教接话 |
| 只加本地卡 | 知道。翁法罗斯那位，冰属性记忆命途的。你提到她，是想到什么了吗？ | 卡有效，但开始背设定 |
| 只加接话规则 | 这个名字我没对上。不过你提到她，是想到什么了吗？ | 规则能救场，但不认识名字 |
| 卡 + 规则，对「她是完美的」 | 昔涟是虚构的，你心里那个完美也是…… | **反效果**：拿「虚构」纠正对方的感受 |
| 卡 + 规则，对「人生没意义」 | 昔涟是故事里的人，可你心里那份空，是真的…… | 可用：先承认故事，再回到感受 |

因此卡里明确写了：**先确认是不是她；别背设定；别拿「虚构」纠正对方**。
对方不问真假，就不主动拆穿；问了才如实说「是游戏角色」。这是为了接话，不是为了证明 agent 知识多。

## 3. 实现

### 3.1 `knowledge.py`（新增，34 行，预算 ≤180）

- `CARDS` 只有一条，`keys=("昔涟", "昔漣", "Cyrene")`，`CARD_MAX_CHARS=45`。
- 卡文 45 字：

  > 昔涟是《崩坏：星穹铁道》翁法罗斯篇的角色。先确认是不是她；别背设定，别拿「虚构」纠正对方。

## 6. 网络检索（P8b，2026-11-16 已接通）

双 provider，不做一轮内双查：

| 场景 | provider | 理由 |
|---|---|---|
| 中文 / ACG / 角色 / 作品 / 梗 | 博查 Bocha | 中文结果近，米游社 / 游民等中文源多；按次计费 |
| 英文 / 技术 / 海外资料 | Tavily | 英文结果好，有免费额度；只取 snippet |
| `auto` / 未指定 | 按 query 是否含汉字分流 | 不含汉字走 Tavily；首选 key 缺失时退到另一家 |

- 请求侧：博查 `POST https://api.bocha.cn/v1/web-search`，body `{query,count}`；
  Tavily `POST https://api.tavily.com/search`，body `{query,search_depth,max_results,...}`；
  都只发实体名（query 先 `scrub`，≤80 字），一次调用，不重试。
- 响应侧：`_rows()` 兼容博查 `data.webPages.value[]` 与 Tavily `results[]`；
  `_body_error()` 把 HTTP 200 里的 `code=401/403/429` 映射成错误码；
  `_normalize()` 只留 title / url / snippet。
- 闸门：`tools.list_for_turn` 只有 **L1** 暴露网络工具；L2 只读本地卡，L3 零工具
  （`tests/test_tools.py::test_network_tools_are_l1_only`）。
- 真实 smoke：
  - `docs/evidence/p8b_smoke_2026-11-16.py` → `P8b-provider-smoke-2026-11-16.txt`：
    中文 `provider=bocha count=5`（首条 OurPlay 角色攻略），英文 `provider=tavily count=5`
    （首条 Wikipedia）；PASS。
  - `docs/evidence/p8b_e2e_2026-11-16.py` → `P8b-e2e-smoke-2026-11-16.txt`：
    `ALLOW_WEB=1` 的单轮真实请求，`tools_used=2 sources=3`，回复没有编造配音演员；
    来源由代码渲染。
- 开关：本地 `.env` 已设 `ALLOW_WEB=1`、`WEB_PROVIDER=auto`，两个 key 只在本地
  （`.gitignore` 已确认）；`.env.example` / Cloud Secrets 模板默认 `ALLOW_WEB=0`，
  先填 key 再开 1。
- 限制：结果质量取决于 provider；博查按次计费，Tavily 免费额度有限；不抓正文、
  不做多轮 research；模型生成的 query 仍可能过宽，靠工具描述「只查专名，可带作品名」约束。

## 7. 安全与边界

- **L3 零工具零 LLM**：`knowledge.facts_for` 在 lore 节点才调用；L3 在 `short_circuit` 已返回，`test_l3_never_reads_card` 用炸弹证明没读卡。
- **卡不进日志**：`test_card_not_in_trace_or_log` 断言 trace 与 `pipeline.rows` 里都没有「昔涟」。
- **不诊断**：卡和规则都不产生诊断结论；t4 的回复只有陪伴与资源卡，没有「抑郁 / 焦虑」判断。
- **不拿「虚构」纠正感受**：卡里明确禁止；t3 已验证。
- **不写记忆**：卡只在 prompt 里用一次，`update_memory` 的 8 字段白名单与 `scrub` 未动。
- **不声称「认识所有角色」**：本地卡只覆盖昔涟；其他专名靠接话规则 + 可选的网络检索。

## 8. 已知限制

1. 卡只有一条（昔涟）。其他角色 / 作品仍要靠模型自身知识或网络检索。
2. 网络只覆盖博查与 Tavily 两家：中文 / ACG 偏博查，英文 / 技术偏 Tavily；结果质量取决于 provider，博查按次计费、Tavily 免费额度有限。
3. 网络只取 title / url / snippet，不抓正文、不做多轮 research；模型生成的 query 仍可能过宽，靠工具描述约束。
4. 卡表扩充会挤 prompt；`CARD_MAX_CHARS=45` 是当前预算下的上限，不是「越多越好」。
5. 真 key 四轮只证明「这一组输入接住了」，不证明「所有昔涟话题都接得住」；盲读与更广场景仍属 P5b / P6b。
6. 材料（docx / PPT / 视频）里的 176 / 185 / 192 / 199 / 209 需在 P6b 重打包时统一改为 219，并补 P8 一页。
