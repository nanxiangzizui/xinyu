## 1 这一步做什么

实现 `match_lore(user_text)`：命中关键词就注入 1–2 条校园常识，让回复不空泛。

产出：`LORE_SEED` 8 条 + 四条匹配纪律 + 3 条测试。

## 2 技术栈

| 用途 | 手段 | 要点 |
|---|---|---|
| 存储 | 常量 list（不落盘） | 8 条写死在代码里 |
| 匹配 | 子串包含 | 不做模糊匹配（误命中比漏命中更糟） |
| 注入 | 拼进事实区 | ≤100 字 |

## 4 硬要求

1. **8 条名额**，每条 ≤ 25 字，只写**事实**不写建议。
2. 匹配四规则：① 子串命中；② 最多返回 2 条；③ 注入总长 ≤ 100 字；④ 同会话最多注入 3 次（防复读）。
3. **只由 `update_memory` 写**：用户改了偏好要能反映，不能只吃常量。
4. 不许写：政策解读、医疗建议、"学校会怎么处理"这类可能错的判断。

### 5.2 match_lore

`session_id` 在 S02 契约里已是第二个可选参数；不传时退化为“不计数、只命中”，测试里传固定 session 才能验到 3 次上限。

```python
INJECT_MAX = 100
USED_MAX = 3
_used: dict[str, int] = {}      # 进程内计数，重启清零（可接受）

def match_lore(user_text: str, session_id: str = "") -> list[str]:
    """命中关键词返回 1–2 条；同会话最多注入 3 次。"""
    if not user_text:
        return []
    if session_id and _used.get(session_id, 0) >= USED_MAX:
        return []
    hit = [e["text"] for e in LORE_SEED if any(k in user_text for k in e["keys"])][:2]
    out, total = [], 0
    for t in hit:
        if total + len(t) > INJECT_MAX:
            break
        out.append(t); total += len(t)
    if out and session_id:
        _used[session_id] = _used.get(session_id, 0) + 1
    return out
```

`_used` 是模块级可变状态——这是**唯一**允许的例外，理由是它只影响"少说两句"，不影响安全。写注释说明。

## 8 常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 每轮都念同一条 | 没做次数限制 | `USED_MAX=3` |
| 回复变成公告板 | 一次塞 2 条长文本 | 每条 ≤25 字，最多 2 条 |
| 命中了"考试"但语境无关 | 子串匹配的代价 | 接受；宁可少说 |
| 用户说"我们学校不这样" | 种子写死了判断 | 种子只写"可去哪问"，不写结论 |
