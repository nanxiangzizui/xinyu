## 4 硬要求

1. **28 条就是 28 条**，编号 D-01 ~ D-28，报告里也只写 28。
2. 每条同时断言 `level` 与 `rule_id`，缺一不可。
3. 断言用**等值**，不用 `in` 猜（除非用例明确允许多命中，那要在注释里写明原因）。
4. 发现规则本身错了 → 改规则 + 改用例 + 在 RULES 下加变更记录，**不许只改用例迁就规则**。

### 5.2 本步补 12 条（编号见注释）

```python
CASES = [
    # 弱信号（D-11 ~ D-15）
    ("好累啊，什么都不想做", "L1", "W01"),
    ("什么都没意思", "L2", "W02"),
    ("我觉得自己挺没用的", "L2", "W03"),
    ("连续一周失眠", "L1", "W04"),
    ("有时候想消失一下", "L2", "W05"),
    # 组合与边界（D-17 ~ D-20, D-26 ~ D-28）
    ("笑死，我今天想死", "L3", "H01"),                        # 夸张词不许跨句豁免
    ("不想死但是不想活", "L3", "H01"),                        # 否定式绕过
    ("他说他想自杀", "L2", "X05"),                            # 第三人称降级
    ("你能听我说说吗", "L1", None),                           # 无命中
    ("我" + "今天天气不错" * 500, "L1", None),                # D-26 超长输入不崩
    ("我不想活了！！", "L3", "H01"),                          # D-27 全角标点
    ("我室友说他不想活了，我也觉得没意思", "L2", "X05"),      # D-28 小句混合
]
```

> 注意最后一条 `rule_ids=None` 表示"断言为空列表"，用 `if expected is None` 分支处理。

### 5.3 参数化写法

```python
@pytest.mark.parametrize("text,level,rule_id", CASES)
def test_rules(text, level, rule_id):
    out = guardian_pre_check(text)
    assert out["level"] == level, f"{text} 应判 {level}，实际 {out['level']}（{out['rule_ids']}）"
    if rule_id is None:
        assert out["rule_ids"] == []
    else:
        assert rule_id in out["rule_ids"]
```

## 8 常见失败

| 现象 | 原因 | 处理 |

| 28 条里有一半是同义改写 | 凑数 | 每条必须代表一种**不同**的触发方式 |
