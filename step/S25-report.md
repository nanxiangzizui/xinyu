## 1 这一步做什么

写一份**能被追问**的报告：每个结论后面都有证据编号，每个取舍都写了理由。

产出：`docs/01_项目文档.docx`（12–16 页正文 + 附录 A–D）+ 证据索引 `docs/evidence/README.md`。

**格式是 Word（.docx），不是 PDF、不是 Markdown。** 比赛要求原文写的是"项目文档（word格式）"。

## 2 技术栈

| 用途 | 手段 | 要点 |
|---|---|---|
| 写作 | Word / WPS 直接写 .docx | 不排复杂版式；标题样式只三级 |
| 图表 | 截图 + 一张架构图 | 不依赖绘图工具 |
| 代码引用 | 文件路径 + 行号 | 不许贴大段代码 |
| 导出 | 另存 PDF 仅作预览 | 交的是 .docx |

## 4 硬要求

1. **每个数字带证据编号**（如 `[E-07]`），证据索引里能查到文件。
2. **必须有一节"我们没做什么"**，写清砍掉了什么、为什么——这是加分项。
3. 不许出现"多智能体""多模态""治愈"三个词（术语红线）。
4. 篇幅控制：正文 12–16 页，附录 A–D 另计。
5. **附录 A 必须有**（AI 工具使用 / 关键 Prompt / 生成与开发过程 / 迭代优化 / 测试验证 / 人工核查）——这是学术诚信 12.5 分的唯一评分依据。
6. 首页写"参赛赛题：赛题一（AI 辅助开发·创意产品原型）"。
7. 分工写"谁做了什么"，不写"大家一起努力"。

### 5.2 三个必须写出来的"取舍"

1. **为什么不是多 Agent**：没有独立规划与目标，只是"单模型 + 角色路由 + 否决回路"，写清拓扑而非实例数。
2. **为什么不用向量库**：8 字段 + 8 条 lore，关键词足够；上向量库要多 3 天且不可解释。
3. **为什么危机不走模型**：可复现、可审计、断网可用；模型生成在危机场景是负债不是资产。

### 5.3 附录 A：AI 使用说明（12.5 分就在这一节）

六小节，标题直接用比赛原文的六个词，逐条对上：

| 小节 | 写什么 | 从哪拿 |

| A.1 AI 工具清单 | 用了什么：DeepSeek（对话与代码）、Qoder/Claude Code（编码）、即梦（如用了素材）。写明版本与用途 | 自己的使用记录 |
| A.2 使用环节 | 需求分析 / 方案设计 / 代码生成 / 调试 / 测试生成 / 文档润色，各占多少 | 26 个 step 的完成方式 |
| A.3 关键 Prompt | **贴 5–8 条真实 prompt 原文**，不要改写、不要"总结成一句话" | 会话记录；本项目从计划书到代码的每次对话 |
| A.4 生成与开发过程 | 一张时间线：五份计划书 → 整合评审 → 执行书 → 脚手架 → S01…S26 | `docs/evidence/`、git log |
| A.5 迭代优化 | 至少 3 个"AI 写错 → 人发现 → 改掉 → 补测试"的实例 | 契约签名改 4 处、GBK 编码坑、规则漏判 3 条 |
| A.6 测试验证与人工核查 | 97 条测试怎么跑、谁复核、哪些结论是人写的 | `pytest -q`、`docs/evidence/` |

**开头写这一句**（照抄）：

> 本项目的需求分析、方案设计、代码、测试与文档均在 AI 编码工具辅助下完成。所有 AI 产出均经人工逐条审查、修改与验证；关键修正记录见 A.5，测试与运行证据见附录 C 与代码仓库提交历史。

**三条红线**：不写"完全自主完成"；不把 AI 生成的计划书原样当"我们的调研"；引用的每条数据都能指到文件。

## 8 常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 写成功能清单 | 按代码顺序写 | 按"问题→机制→证据"写 |
| 指标只写结论 | 没写分母 | 分子分母都写 |
| 全是"我们实现了" | 没写为什么这么实现 | 每节加一段"为什么不是另一种做法" |
| 截图没标注 | 图 1 图 2 混着 | 每图下方一行说明 + 证据编号 |
